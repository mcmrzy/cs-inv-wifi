# ESP32-C2 当前改造状态与 BLE 常驻待办

> 日期：2026-07-20  
> 硬件：ESP32-C2 ECO4 rev2.0，4 MiB Flash  
> ESP-IDF：v5.5.4  
> 已提交基线：`b46f2db`（`feat(esp32c2): 重构配网、遥测与安全 OTA`）  
> 当前状态：基线之后的启动内存修复尚未提交；最终镜像已烧录 COM12 进行启动验证。

本文记录当前已经实现的 ESP32-C2 改造、真机验证结果、资源边界，以及后续 BLE 常驻改造必须处理的问题。文中“当前行为”均以工作区代码为准；“待办设计”尚未实现。

## 1. 身份与职责（Identity & Responsibility）

### 1.1 涉及文件

- `esp32c2_idf/main/app_main.c`：系统初始化、Wi-Fi/AP、HTTP API 和任务启动顺序。
- `esp32c2_idf/main/ap_api_server.c`：供 App 使用的 AP 配网与本地 OTA HTTP API。
- `esp32c2_idf/components/ble_prov/ble_prov.c`：当前 ESP-IDF `wifi_prov_mgr` BLE 配网封装。
- `esp32c2_idf/main/state_machine.c`：Wi-Fi/MQTT 状态机、按键行为和配网回调。
- `esp32c2_idf/main/ota_service.c`：本地 HTTP 与远程 MQTT 共用的 OTA 服务。
- `esp32c2_idf/main/offline_cache.c`：离线遥测批量缓存。
- `esp32c2_idf/sdkconfig`、`esp32c2_idf/sdkconfig.defaults`：4 MiB、Wi-Fi 与 NimBLE 内存配置。
- `tools/tests/esp32c2_ota_contract.test.mjs`：ESP32-C2 启动、AP API、BLE 生命周期和 OTA 合同回归测试。

### 1.2 当前核心职责

设备当前同时承担：

- UART 接收逆变器数据和命令。
- STA 连接用户 Wi-Fi，通过 TLS MQTT 上报遥测、接收控制和远程 OTA。
- 常驻 SoftAP，向 App 提供配网、状态查询和本地 OTA API。
- 无网络时将遥测批量写入 SPIFFS，联网后以 QoS 1 重传并等待 PUBACK。
- 对 ESP 与 ARM 固件执行统一的 SHA-256、Ed25519 和安全版本校验。
- 在按键触发后从 AP/HTTP 切换到 BLE 配网模式。

### 1.3 上下游关系

- 上游：ARM UART、手机 App、MQTT Broker、本地 HTTP OTA 上传端。
- 下游：Wi-Fi 驱动、NVS、SPIFFS、ESP OTA 分区、ARM UART OTA、MQTT 状态主题。

## 2. 架构模型（Architectural Model）

### 2.1 当前启动顺序

1. 初始化 NVS、事件循环、STA/AP netif 和 Wi-Fi 驱动。
2. 初始化持久化、UART、LED、SPIFFS 离线缓存和统一 OTA 服务。
3. SN 已存在时才初始化 MQTT；无 SN 时等待 ARM 通过 UART 提供，避免启动阶段产生无意义错误。
4. 先设置 `WIFI_MODE_APSTA` 并启动 Wi-Fi。
5. 启动 App HTTP API。
6. 启动 SNTP、状态机、主循环和 OTA 启动健康检查任务。
7. 默认不启动 BLE，防止 AP、HTTP、BLE 同时申请内存导致堆耗尽。

### 2.2 线程模型

- `main_task`：完成一次性初始化，随后退出。
- Wi-Fi 驱动任务：ESP-IDF 创建，当前栈为 6144 B。
- HTTP server 任务：处理 7 个 App API，栈为 4096 B。
- `main_loop`：2 ms 周期处理 UART、按键、LED、状态机、离线缓存和 OTA 健康心跳，栈为 4096 B。
- OTA 健康检查任务：确认新固件主循环存活后取消回滚。
- 本地 OTA 工作任务：当前上传时临时创建，栈为 6144 B。
- MQTT 任务：仅 SN、密钥和网络条件满足后运行，配置栈为 4096 B。
- NimBLE Host 任务：仅进入 BLE 配网模式后创建，配置栈为 3072 B。

### 2.3 同步与所有权

- OTA 服务使用互斥和原子状态，保证本地 OTA 与远程 MQTT OTA 不能并发占用设备。
- 离线 MQTT 重传通过队列等待 `MQTT_EVENT_PUBLISHED`，只有收到 PUBACK 才删除缓存记录。
- HTTP server 拥有 URI handler 和 socket 会话；停止服务后释放 HTTP 任务及服务上下文。
- 当前 BLE manager 在 `WIFI_PROV_END` 中 `deinit`，凭据先暂存，释放 BLE 配网内存后才回调 Wi-Fi 状态机。

## 3. 业务流程（Logic Workflow）

### 3.1 AP 配网与本地 OTA

设备启动后 SoftAP 和 HTTP API 常驻，不提供浏览器网页。App 可直接调用：

- 扫描附近 Wi-Fi。
- 写入 SSID/密码并连接 STA。
- 查询连接状态。
- 查询 ESP/ARM 固件版本和 OTA 状态。
- 上传 ESP 或 ARM 固件、查询进度、取消任务。

本地和远程 OTA 进入同一 `ota_service`，共用目标锁、签名验证、哈希校验、安全版本校验、进度快照和错误码。

### 3.2 当前 BLE 配网流程

短按按键 0.2～5 秒后：

1. 停止 HTTP API，释放 HTTP server 内存。
2. 将 Wi-Fi 从 APSTA 切换为 STA，释放 SoftAP 相关内存。
3. 启动 ESP-IDF `wifi_prov_mgr` + NimBLE 配网。
4. 配网成功时先保存凭据；收到 `WIFI_PROV_END` 后释放 manager/BTDM 内存，再配置 STA 并恢复 AP HTTP API。
5. BLE 启动失败时恢复 APSTA 和 HTTP API。

长按 5 秒仍执行恢复出厂设置。

### 3.3 OTA 流程

- 远程入口：MQTT OTA 命令提供 URL、目标、版本、大小、SHA-256、Ed25519 签名和安全版本。
- 本地入口：HTTP Header 提供相同元数据，请求体流式传输固件。
- ESP 目标：流式写入非运行 OTA 分区，校验后切换启动分区，重启后通过健康检查确认或回滚。
- ARM 目标：数据暂存/流式送入 ARM OTA 状态机，通过 UART 分包、ACK、重试和结束确认完成升级。
- 任意时刻只允许一个 OTA 任务；ESP 和 ARM 分别保存单调递增的安全版本。

### 3.4 离线缓存流程

- 遥测先进入 RAM 批次，达到批量上限或超时后写 SPIFFS，避免每条消息触发 Flash 写入。
- 网络恢复后后台读取批次，以 MQTT QoS 1 发布。
- 收到 PUBACK 后才删除记录；超时或断线时保留数据等待下次重试。

## 4. 接口与契约（Interfaces & Contract）

### 4.1 AP HTTP API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/scan` | 扫描附近 Wi-Fi |
| POST | `/config` | 保存 SSID/密码并触发连接 |
| GET | `/wifi_status` | 查询 Wi-Fi 和状态机状态 |
| GET | `/ota/info` | 查询 ESP/ARM 版本及签名策略 |
| GET | `/ota/progress` | 查询当前 OTA 快照 |
| POST | `/ota/upload` | 本地流式上传 ESP/ARM 固件 |
| POST | `/ota/cancel` | 取消允许取消的 OTA 任务 |

HTTP server 当前参数：任务栈 4096 B、最多 7 个 URI handler、最多 3 个打开 socket。

### 4.2 当前 BLE API 与 App 的不一致

当前固件使用 ESP-IDF 官方 `wifi_prov_mgr`/protocomm BLE 服务；App 的 `BleProvisioningService` 则期待以下自定义 Service：

`43534956-5052-1000-8000-00805f9b34fb`

App 还期待 SN、固件、MAC、SSID、密码和状态等自定义 Characteristic。当前 ESP32-C2 固件没有实现这套自定义 GATT 特征，因此当前 BLE 只完成了资源和生命周期修复，尚未完成与 App 协议的实际对齐。

旧文档 `docs/BLE_Provisioning_Protocol.md` 描述的是自定义 GATT 方案，不能视为当前 ESP32-C2 已实现行为。

### 4.3 BLE 常驻新需求（尚未实现）

已确认的需求：

- BLE 必须常驻，不只是配网期间广播。
- App 平时通过 BLE 持续读写设备数据。
- ESP/ARM OTA 期间允许暂停 BLE，OTA 完成或设备重启后恢复。

尚未确定：BLE 业务通道需要完整镜像 MQTT 遥测/告警/控制，还是只提供摘要和常用控制。该选择会影响 GATT 特征设计、分包、通知频率、背压和鉴权方式。

## 5. 约束、安全与性能（Constraints & Safety）

### 5.1 已复现的启动故障

原始启动顺序先启动 BLE，再启动 APSTA 和 HTTP，真机出现：

- NimBLE 广播设置错误 `rc=687`。
- `esp_wifi_set_mode(WIFI_MODE_APSTA)` 返回 257（内存不足）。
- `httpd_create` 无法分配 HTTP server 实例。
- App API 启动失败。

根因不是 4 MiB Flash 容量，而是 ESP32-C2 约 108 KiB 动态 RAM 中同时常驻 Wi-Fi、HTTP、BLE、缓存和任务栈，导致可分配堆及最大连续块耗尽。

### 5.2 COM12 真机内存数据

最终 AP/API 默认启动路径：

| 阶段 | Free heap | Largest block | 增量占用 |
|---|---:|---:|---:|
| APSTA 前 | 44,020 B | 43,008 B | 基准 |
| Wi-Fi 启动后 | 38,744 B | 37,888 B | 约 5.2 KiB |
| HTTP App API 后 | 31,280 B | 31,232 B | 约 7.3 KiB |
| 主循环等任务后（前一轮测量） | 约 26.7 KiB | — | 约 4.5 KiB |

当 AP、HTTP 和 BLE 同时启动时，堆从约 26.7 KiB 降到 780 B，历史最小值 432 B。该状态虽然可能暂时不崩溃，但无法承受 socket、MQTT TLS、请求解析或 OTA 临时分配，因此当前版本采用分时切换。

HTTP 的约 7.3 KiB 主要包括 4096 B 任务栈，以及 server context、任务控制块、控制队列、监听/控制 socket、会话表、URI 节点和同步对象；业务响应代码位于 Flash，不是主要占用来源。

### 5.3 当前静态和临时 OTA 内存

- `ota_service.c`：4096 B ESP/统一传输缓冲，当前为静态数组。
- `arm_ota.c`：8192 B ARM 流缓冲，加约 480 B 分包缓冲，当前为静态数组。
- `offline_cache.c`：初始化时为 10 条缓存记录分配约 5.8 KiB RAM。
- 本地 OTA 上传：临时创建 6144 B 工作任务栈，并分配约 0.6 KiB manifest/context。

### 5.4 BLE 常驻改造前置条件

要让 AP、HTTP、MQTT TLS 和 BLE 长连接同时工作，不能只缩减 HTTP server。后续至少需要：

1. 将离线批次改为首次产生离线数据时再分配。
2. 将 ESP 4 KiB 与 ARM 8 KiB OTA 缓冲改为任务开始时分配，结束时释放。
3. 评估本地 OTA 复用 HTTP task，取消额外 6 KiB OTA worker stack。
4. 实现与 App UUID 一致的自定义 NimBLE GATT 服务，替换当前 `wifi_prov_mgr` 常驻方案。
5. 为持续数据通道定义最大帧、分包、通知频率、队列上限、丢弃/背压和重连策略。
6. 在具有 SN、MQTT 密钥且 TLS 已连接的真实状态下重新测量，不得以“无 MQTT 的启动堆”作为验收数据。
7. 设定硬性内存水位：正常 BLE + AP + MQTT 运行时建议至少保留 10～15 KiB free heap 和足够的最大连续块。
8. OTA 开始前停止 BLE 业务通道并释放可回收资源；OTA 完成后恢复，ESP OTA 则由重启恢复。

### 5.5 安全约束

- BLE 写控制命令和 Wi-Fi 密码不能仅依赖“附近可连接”；后续常驻协议必须增加绑定、会话鉴权或加密授权。
- BLE 回调中不得执行长时间 UART、Flash 或网络阻塞操作，应投递到有界队列交给业务任务处理。
- OTA 继续强制 Ed25519 + SHA-256 + 安全版本校验，本地 AP 上传不能绕过验证。
- MQTT 与 BLE 同时写同一控制状态时必须使用统一命令入口和去重规则，避免竞态与重复执行。

### 5.6 当前验证结果

- 固件合同测试：27/27 通过。
- ESP-IDF 完整编译通过。
- 最终镜像大小：`0x1304f0`，最小 OTA App 分区剩余约 32%。
- COM12 烧录成功，所有写入块哈希校验通过。
- 最终 AP/API 启动日志未再出现 `rc=687`、错误 257、HTTP 分配失败或 SN 未设置错误。
- 尚未完成：物理按键 BLE 配网端到端测试、自定义 App GATT 对齐、MQTT TLS + BLE + AP 并发压力测试。
