📋 概览

设备连接方式

方式场景地址
HTTP API局域网配网、OTA升级http://192.168.4.1 (AP模式)
http://{device_ip} (STA模式)
MQTT云端数据上报、远程控制mqtts://jiuxiaoyw.online:8883
UARTARM芯片通信115200 baud, 8N1

MQTT 主题结构

cs_inv/{sn}/           # 设备根主题
├── data/
│   ├── info           # 设备信息
│   ├── status         # 运行状态
│   ├── ac             # 交流输出数据
│   ├── battery        # 电池数据
│   ├── pv             # 光伏输入数据
│   ├── energy         # 能量统计
│   ├── cells          # 电芯数据
│   └── alarm          # 告警数据
├── cmd                # 控制命令 (下发)
├── cmd_result         # 命令执行结果 (上报)
├── ota/
│   ├── cmd            # OTA命令 (下发)
│   ├── cmd_ack        # OTA命令确认 (上报)
│   └── status         # OTA状态 (上报)
└── status             # 设备在线状态 (LWT)

📥 MQTT 下发 (云端 → 设备)

SUBSCRIBE cs_inv/{sn}/cmd

控制命令 (透传给ARM)

{
  "cmd": "set_control",
  "params": {
    "power_limit": 5000
  },
  "task_id": "task_123"
}

支持的命令类型:

cmd说明params示例
set_control设置控制参数{"power_limit": 5000}
set_alarm设置告警{"code": 1} 触发告警
{"code": 0} 清除告警
set_sim_param设置模拟参数{"soc": 50}
reset重置设备{}

🔄 OTA 升级

方式一: HTTP 本地升级

设备连接AP热点后，通过HTTP接口升级

GET /ota/info

获取设备固件信息

{
  "esp_version": "V1.2.0.20260629",
  "arm_version": "V1.2.3.20240510",
  "free_heap": 123456,
  "chip": "ESP32-C3"
}
POST /ota/upload

上传固件文件

ESP固件 (推荐):

Content-Type: application/octet-stream
Body: [二进制固件数据]
限制: 最大 2MB

ARM固件:

Content-Type: multipart/form-data
Body: file=[文件] &target=arm
限制: 最大 256KB
GET /ota/progress

查询升级进度 (每秒轮询)

{
  "target": "esp",
  "progress": 50,
  "status": "downloading",
  "message": "下载中..."
}

status值: idle | downloading | writing | verifying | done | error

方式二: MQTT 远程升级

通过MQTT下发升级命令，设备从URL下载固件

SUBSCRIBE cs_inv/{sn}/ota/cmd

OTA命令

// 开始升级
{
  "command": "start",
  "target": "esp",
  "url": "https://example.com/firmware.bin"
}

// 查询状态
{
  "command": "query"
}

// 停止升级
{
  "command": "stop"
}
PUBLISH cs_inv/{sn}/ota/cmd_ack QoS 1

OTA命令确认

{
  "ack": true,
  "task_id": "xxx",
  "message": "开始升级",
  "timestamp": 1782703114

告警代码定义

代码级别描述触发条件
1fault逆变器过温保护温度 > 65°C
2fault电池过压保护电压 > 58V
3fault电池欠压保护电压 < 46V
4fault输出过载保护负载 > 95%
5fault直流母线过压母线电压异常
6warning逆变器温度过高温度 55~65°C
7warning电池SOC过低SOC < 25%
8warningPV输入异常PV参数异常
9warning电芯压差过大电芯压差异常
10info系统启动完成设备启动
11info进入待机模式待机状态
12info恢复并网运行并网恢复

💾 离线缓存

当MQTT未连接时，设备会自动缓存待发送数据。连接恢复后自动发送缓存数据。
参数值说明
最大缓存条数1000超过后删除最老数据
缓存保留时间7天超过自动清理
重试间隔30秒连接恢复后定期重试发送

🔌 UART 协议 (ESP32 ↔ ARM)

波特率: 115200, 数据位: 8, 停止位: 1, 校验: 无

帧格式

[HEADER 0xAA] [CMD 1B] [LEN_H 1B] [LEN_L 1B] [DATA ...] [XOR 1B]

命令码定义

命令码方向说明
0x01ESP→ARM设置MQTT Broker
0x02ARM→ESP发布MQTT消息
0x03ESP→ARM收到MQTT命令
0x04ARM→ESP命令执行结果
0x05ESP→ARM恢复出厂设置
0x06双向心跳
0x08ESP→ARM设置序列号
0x09ESP→ARM设置设备密钥
0x0AESP→ARM设置AP热点名称
0xFE双向ACK确认
0xFF双向NACK否认

OTA相关命令

命令码方向说明
0x10ESP→ARM通知进入IAP模式
0x11ESP→ARM发送固件数据包
0x12ESP→ARM传输结束，校验跳转
0x13ARM→ESP确认收到
0x14ARM→ESP请求重传
0x15ARM→ESP上报固件信息

📊 数据流示意

正常运行流程

1 ARM 采集逆变器数据
↓
2 ARM 通过 UART (CMD_PUBLISH) 发送到 ESP32
↓
3 ESP32 添加时间戳，通过 MQTT 上报云端
↓
4 云端接收并处理数据

控制命令流程

1 云端通过 MQTT 发送控制命令到 cs_inv/{sn}/cmd
↓
2 ESP32 通过 UART (CMD_COMMAND_RECV) 转发给 ARM
↓
3 ARM 执行命令，通过 UART (CMD_COMMAND_SEND) 返回结果
↓
4 ESP32 通过 MQTT 发送结果到 cs_inv/{sn}/cmd_result

离线缓存流程

1 MQTT 未连接时，数据自动缓存到 Flash
↓
2 连接恢复后，自动发送缓存数据
↓
3 每30秒检查一次，直到所有缓存发送完毕
