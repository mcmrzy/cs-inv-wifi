# ARM 固件问题清单 — 运行参数（RunParamDef）上报

> **文档版本**: v1.0
> **适用产品**: CS-L10-6K2 / CS-I10-6k2 48V 单相离网逆变器
> **适用对象**: 辰烁科技 ARM 端开发人员
> **核查依据**: `App(8)\App`（2026-09-18 版）源码 `Collector/Collector.c::ReadRunParam()`、`Collector/CollectorParamAddr.h::RunParamDef`、`ComDSP/UsartDsp.c`（DSP TxBuf 解析，量纲权威来源）
> **实机数据**: 设备 H1ZZX0023900002P，200B 新版布局心跳（2026-09-20）
> **最后更新**: 2026-09-20

---

## 0. 结论（TL;DR）

新版 200B `RunParamDef` 的**布局与寄存器分配本身没有问题**（已逐字节核对，与寄存器报告一致）。但**填充赋值存在 5 类问题**，其中 P0-1 会导致现场数据不可恢复：

| 编号 | 问题 | 严重度 | 影响字段 |
|------|------|--------|----------|
| P0-1 | **电流 ×100 写入 16 位字段导致回绕**（乘法不溢出，是 `(u16)/(s16)` 赋值截断），实机已发生 | 严重 | Buck1Curr、Buck2Curr、OutputCurr（u16，>6.55A 回绕）、Ibus、IinvtA（s16，>±3.28A 回绕且可能翻号） |
| P0-2 | `ReadRunParam` 的 `malloc(256)` 后**未 memset**，未赋值字段把随机堆内存发到云端 | 严重 | PvTemp、InvCurr、TransformerTemp、PairedSocket、OnlineSocket、OnSocket |
| P0-3 | `Warning` 高 32 位未清零（`tempWarningCode1` 未初始化） | 高 | Warning bit16~31 |
| P1-1 | `Sload`（视在功率）恒 0，与有功 6187W / 电流 27A 矛盾 | 中 | OutputVA、ACInVA、ACChrVA、ACDisChrVA |
| P1-2 | `Pbat`（电池功率）恒 0，与电池 -133.4A / 49V 矛盾 | 中 | BatChrWatt、BatDisChrWatt |
| P1-3 | 单位注释缺失/不一致（LoadPercent、IgridA、IloadA、BusVolt、InvtFreq） | 中 | 见 §4 |
| P2-1 | ACChr / ACDisChr 与 ACIn 同源（过渡方案），语义待确认 | 低 | ACChrWatt/VA、ACDisChrWatt/VA |

## 1. P0-1 电流 ×100 写入 16 位字段，实机已回绕

### 1.1 现象

现场心跳（设备 H1ZZX0023900002P，满载约 100%）中 `OutputCurr` 寄存器读数为 **8556**，按任何单位都得不到合理电流。

### 1.2 定位

```c
/* Collector.c */
pRunParam->Buck1Curr  = (u16)((u32)SysParam.Ipv1 * 100);     // :535 / :536（Buck2Curr）
pRunParam->OutputCurr = (u16)(SysParam.IloadA < 0 ? 0 : (u16)SysParam.IloadA*100);  // :496
pRunParam->Ibus       = SysParam.Ibus*100;                    // :530  字段类型为 s16
pRunParam->IinvtA     = SysParam.IinvtA*100;                  // :488  字段类型为 s16
```

乘法在 u32 / int 内**不会溢出**，但赋值给 `u16`（或 `s16`）字段时按 2¹⁶ 取模**截断**，高位丢失：

| 字段 | 字段类型 | DSP 源单位 | 回绕阈值 |
|------|----------|-----------|----------|
| Buck1Curr / Buck2Curr（`Ipv1/2×100`） | u16 | 10mA | 源值 > 655 → **> 6.55 A** |
| OutputCurr（`IloadA×100`） | u16 | 0.01A | **> 6.55 A** |
| Ibus（`Ibus×100`） | **s16** | 0.01A | **> ±3.28 A**，且负数会翻号 |
| IinvtA（`IinvtA×100`） | **s16** | 0.01A | **> ±3.28 A**，且负数会翻号 |

### 1.3 实机反解（证明回绕真的发生了）

回绕前的真值必须形如 `8556 + k×65536` 且为 100 的倍数（因为写的是 `IloadA×100`）：

| k | 回绕前真值 | IloadA（0.01A） | 安培 | ×228V 推算功率 |
|---|-----------|----------------|------|---------------|
| **4** | **270700** | **2707** | **27.07 A** | **6172 W** ← 唯一物理合理 |
| 29 | 1909100 | 19091 | 190.91 A | 43527 W ✗ |

同一帧内 `OutputWatt = 6187 W`（1W）、`ACOutputVolt = 228 V` ⇒ 6187/228 = **27.14 A**，与 27.07 A 吻合（差 0.2%，为 DSP 两个量各自测量误差）。

**结论：设备当时确实输出约 27 A，ARM 存进去的却是 8556。**

### 1.4 影响

1. 回绕后的残值无法还原：直接读数按 0.1A 解为 855.6A、按 0.01A 解为 85.56A，**两者都是错的**；正确值 27.07A 应存为 271。候选真值间隔 655.36 A，只能靠功率交叉猜测，属猜数据。
2. 按正确的契约单位换算时，这些字段在**满载工况下必然出错**（Buck/输出电流 > 6.55 A 是常态）。
3. 我们云端目前只能靠"越界即丢弃"兜底，但回绕值常常**不越界**，会显示为"看似正常的错误数字"。

### 1.5 修法（建议按此改）

```c
/* 0.1A 契约单位：源值 /10；u16 可表 6553.5A，永不回绕 */
pRunParam->Buck1Curr  = (u16)(SysParam.Ipv1  / 10);   /* 10mA  → 0.1A：15A → 150 */
pRunParam->Buck2Curr  = (u16)(SysParam.Ipv2  / 10);
pRunParam->OutputCurr = (u16)(SysParam.IloadA < 0 ? 0 : SysParam.IloadA / 10);
pRunParam->ACChrCurr  = (u16)(SysParam.IgridA < 0 ? 0 : SysParam.IgridA / 10);  /* 见 §4 */

/* 0.01A 契约单位：源值直传（不要 ×100） */
pRunParam->Ibus   = (s16)SysParam.Ibus;     /* 0.01A → 0.01A */
pRunParam->IinvtA = (s16)SysParam.IinvtA;   /* 0.01A → 0.01A */
```

## 2. P0-2 `ReadRunParam` 缓冲区未清零 → 随机值上云

### 2.1 定位

```c
/* Collector.c:408 附近 */
pmemaddr = (u8*)malloc(256);      /* 没有 memset */
pRunParam = (RunParamDef *)pmemaddr;
```

本函数**未赋值**的字段（其余赋值代码已注释或从未编写）：`PvTemp`、`InvCurr`、`TransformerTemp`、`PairedSocket`、`OnlineSocket`、`OnSocket`。

### 2.2 实机证据

| 字段 | 实测值 | 后果 |
|------|--------|------|
| PairedSocket / OnlineSocket / OnSocket | 25108 | 云端"插槽状态"显示 25108 |
| InvCurr | 区间随机（曾见 13340 等） | "逆变器电流"显示 1334A |
| PvTemp / TransformerTemp | 随机 | 温度列显示无意义数值 |

### 2.3 修法

```c
pmemaddr = (u8*)malloc(256);
if (!pmemaddr) return;
_memset((u8*)pmemaddr, 0, 256);      /* ← 新增：未赋值字段一律为 0 */
```

若这些功能长期不实现，建议在协议文档中明确标注"暂不支持"，便于云端把对应字段判为无效而不是显示 0。

## 3. P0-3 `Warning` 高 32 位未初始化

### 3.1 定位

```c
/* Collector.c:586 */
pRunParam->Warning = (tempWarningCode1.word << 16) | tempWarningCode;
```

`tempWarningCode1` 的 4 个 bit 赋值（parallelNoBat / fan2Locked / ParaVerDiff / UnstableGridFrq）**全部被注释**，局部变量未初始化 → bit16~31 为栈上随机值。实机该位读到 **20078**。

### 3.2 影响

云端按位解析告警时，bit16~31 的随机值可能被解读为虚假告警（当前我们在网关侧强制 `& 0xFFFF` 屏蔽，但源头应修）。

### 3.3 修法

```c
tempWarningCode1.word = 0;           /* 先清零，再按需置位 */
/* 或恢复那 4 个 bit 的赋值 */
```

## 4. P1 级问题

### P1-1 `Sload` 恒 0

`OutputVA = Sysload`（1VA 直传）实机为 0，而同帧有功 6187W、输出电流 ≈27A。三相/单相负载下 **VA ≥ W** 恒成立，视在功率为 0 说明 `SysParam.Sload` 未从 DSP 取得或未解析（建议核对 `UsartDsp.c` 中 `Sload = RxBuff[35..36]` 的字节偏移与 DSP 实际发送顺序）。受影响的契约字段：`output_apparent_power`、`ac_input_apparent_power`、`ac_charge_apparent_power`、`ac_bypass_apparent_power`。

### P1-2 `Pbat` 恒 0

`BatChrWatt / BatDisChrWatt` 由 `SysParam.Pbat` 符号拆分而来，实机两者均为 0，而同帧电池 `Batvolt = 49.00V`、放电电流 `133.4A`（放电功率应约 6.5kW）。请确认 `Pbat` 的 DSP 来源与符号约定（充正/放负）。

### P1-3 单位注释缺失 / 不一致（会增加双方联调成本）

| 位置 | 现状 | 建议 |
|------|------|------|
| `UsartDsp.c:295` `SysParam.LoadPercent` | 注释只有"//单位"，为空 | 实测 100 对应满载（Pload 6187W ≈ 6.2kW 额定；电池 133.4A×49V ≈ 6.5kW），推断为 **1%**，请确认 |
| `UsartDsp.c:277` `IgridA` | 注释 0.01A，另有资料写 0.1A，互相矛盾 | 以 DSP TxBuf 为准统一，建议注明"DSP ×100" |
| `UsartDsp.c:291` `IloadA` | 注释 0.01A（报告曾标注为"?"） | 同上，补全 |
| `CollectorParamAddr.h` `BusVolt` | 注释"0.1V"，但代码 `BusVoltage(0.1V)×10` → 实际 **0.01V**（实机 37350 = 373.50V） | 注释改为 0.01V |
| `CollectorParamAddr.h` `InvtFreq` | 注释 0.1Hz，但代码 `SysParam.InvtFreq(0.1Hz)×10` → 实际 **0.01Hz** | 统一为 0.01Hz（或改为直传并保留 0.1Hz） |

### P2-1 ACChr / ACDisChr 与 ACIn 同源

`ACChrWatt = ACChrVA = ACDisChrWatt = ACDisChrVA = ACInWatt/ACInVA`（`Collector.c:548-551` 注释说明为过渡方案）。目前云端 4 个"交流充电/旁路"字段显示的都是市电输入值，请在语义确定后更换数据源或明确标注"暂与市电输入同源"。

### P2-2 `Ibus` 数值无法解释（不发布，但需修）

实机 `Ibus = 21008`，按 0.01A（210.08A）、0.1A（2100.8A）均不合理；同时该字段是 s16 + `×100` 写法，存在 §1 所述回绕风险。建议改为直传（0.01A）后实测核对。

## 6. 寄存器区边界

**未定义区**：协议允许寻址到 0x0454，但结构体只到 0x044B，`0x044C~0x0454` 返回的是缓冲区外的数据。建议把 `RunParamEndIndex` 收敛到结构体末尾（0x044B），或明确该区域为保留。

## 7. 验证自测清单（改完后请按此自查）

1. **电流不回绕**：PV 侧接 ≥10A 负载、输出侧带 ≥50% 负载，读回 `Buck1Curr/OutputCurr` 应约为 **电流(A)×10** 的量级（例：14A → 140、满载 27A → 271），不应出现 18928、8556 之类残值。
2. **无用字段为 0**：`PvTemp/InvCurr/TransformerTemp/PairedSocket/OnlineSocket/OnSocket` 读回全 0。
3. **Warning 高位为 0**：`Warning & 0xFFFFFFFF0000` == 0。
4. **视在/电池功率非 0**：带载工况下 `OutputVA`、`BatDisChrWatt` 应与 `OutputWatt`、`Vbat×Ibat` 同量级。
5. **单位一致性**：`LoadPercent=100`（满载）、`BatVolt=4900`（49.00V）、`BusVolt≈37350`（373.50V）、`ACOutputFreq≈4970`（49.70Hz）。
