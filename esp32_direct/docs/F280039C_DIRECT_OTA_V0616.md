# ESP32 -> F280039C OTA / 0.6.16-dsp-ota

## 接入

云端和蓝牙继续使用原有 target=dsp 入口；镜像由现有服务下载/接收并暂存。
提供 SHA256 时先核对哈希。DSP UART0 原 owner 执行所有升级收发，
升级期间暂停 00/01/02/03/04，BMS 保留原有独立升级协议。
没有 ARMU、Collector PULL、ARM 中转，也不新增争抢 UART 的读取任务。
ESP 引脚沿用本机 GPIO1 TX / GPIO0 RX，不把 DSP 的 GPIO22/23 当作 ESP 引脚。

移植依据为用户提供的 docs/esp32/dsp_ota.c/h。为了低内存设备，使用现有
staging 文件流式读取，只分配 1029 字节的 DSP 帧缓冲，不把整镜像放入 RAM。
正常通信和 TLS 配置继续保留。

## 协议

| 阶段 | 指令/回复 | 超时和重试 |
|---|---|---|
| 进入 Boot | 01 05 42 00 00 00 00 73 9A -> HR | 2秒，最多5次 |
| 擦除 | 13字节擦除帧 -> 固定13字节应答 -> CR | 应答3秒、完成12秒，整个阶段最多5次 |
| 数据 | 02 AddrH AddrL 数据 CrcH CrcL -> CR | 3秒，最多10次，重发同一帧 |
| 结束 | 02 00 FF 45 4F 54 | 无ACK，等待1秒 |

地址按 `(0x01FE + 0x00FF * index) & 0xFFFF`，允许超过第255包后绕回。
CRC16-Modbus 0xFFFF/0xA001，覆盖包头+地址+数据，高字节在前。
实际提供的 C 模块末包按剩余长度发送，没有填充；本实现保留这一行为。
最多367包/375808字节。失败或取消不发送 EOT，保持 Boot 待恢复，
不继续向升级态 DSP 注入正常轮询或持久设置。
超时用实际单调时钟，UART 单次等待不超过25ms，并持续更新任务健康心跳。

进入 Boot 前，按提供模块验证：长度至少64字节、偶数、LB掩码匹配0x0048、
偏移4/5为5A5A。错误镜像不发送CMD42，更不擦除。
提供文件只检查 magic 高半字，没有定义完整镜像头的长度/CRC32字段和覆盖范围。
本次不猜测该格式，也不宣称ESP已执行完整镜像CRC32验证。
DSP Boot 的严格整镜像检查属于用户说明中的目标行为，需对应Boot源码/实机确认。

## USB 管理员控制

不回显、不记录密码；这些命令只提交作业给同一个 DSP UART owner。

```
dsp_boot <管理员密码>
dsp_run <管理员密码>
dsp_reboot <管理员密码>
```

- dsp_boot：发送CMD42并等待HR。成功表示收到Boot握手；保持正常DSP轮询暂停。
- dsp_run：发送EOT并等待1秒，恢复轮询。成功只表示EOT已提交，App启动未确认。
- dsp_reboot：CMD42/HR后发送EOT，完成一次Boot进入/退出请求。
- 失败/不确定Boot状态保持暂停；可重试升级或明确执行dsp_run恢复。
- OTA运行、待保存设置或其他控制作业存在时拒绝并发请求。

CMD42要求DSP App实现对应交接。已提供旧ArmComm.c只设置RecvRebootCmd，
ESP无法直接写DSP RAM魔数，也无法代替DSP App执行跳转。
新DSP App必须按其实际Boot链接布局预留共享标志、停机处理并进入Boot。
不要仅凭ESP发送成功推断DSP已复位；HR才是此协议的握手证据。

OTA成功状态表示全包CR和EOT传输完成，尚无已确认的新App版本查询。
升级后仍需观察新App横幅/版本及新的03/04数据，再完成物理验收。

## 屏幕刷新

显示每1秒重绘一次，按键仍立即响应。只缓存真实收到的04数据；
短暂缺帧或取锁失败时保留最后有效值，2~5秒保留期间主页显示Last Ns，
到5秒显示--。没有样本时仍是--，真实0保持0。
OTA或手动Boot期间清缓存，恢复后必须收到新的样本。
云端实时/告警原有2秒新鲜度规则和110ms通信时隙不变。

## 验证和刷写

回归包括：无头/奇数/超大镜像零发送、同帧重试、完整擦除重试、短尾包、
367包及地址绕回、噪声中的真实截止时间、失败不EOT、UART owner独占、
管理员鉴权、显示锁抖动、5秒失效与OTA恢复。
以发布包 validation 中的实际结果为准；未烧录、未实测DSP Flash升级。
已有设备只刷 device/app.bin，保留SN、WiFi、ESP用户参数与不可变默认包。
