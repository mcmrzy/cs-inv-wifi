# 当前屏幕故障审查

## 已有现场证据

- SP-TFT028F276(1).pdf 指定 ST7789P3，4SPI，240x320。
- 用户确认 SCK6、SDA7、RS9、RESET10及屏幕连接器对应关系全部导通。
- 用户实测 VCC=2.89V、RESET=3V、CS=0V；RS上拉为10kΩ。
- 硬件SPI1MHz、GPIO模拟SPI两版均执行完三色发送而屏幕仅有背光。GPIO9/10读回高低正确；未取得屏幕端波形或控制器返回值。
- 最小初始化版也失败：用户日志确认LCD MINIMAL_INIT、CS=-1，约15.7秒发送RED、27.6秒发送GREEN，屏幕仍无变化。不能宣称电源/gamma参数替换已修复问题，也不能排除代码发送故障。
- 终止式读回版：SCL6/SDA7/RS9/RESET10均set0/read0、set1/read1；MADCTL期望A8，实际FF，match=NO。未取得控制器返回值证据。模块读回路径支持尚未确认，不能认定屏幕损坏，也不能将READY解释为屏幕正常。此诊断版读回后不再发送显示数据。

## 代码审查结果

GPIO模拟SPI确实为每字节8位MSB-first、SCL空闲低、数据在上升沿前稳定；D/C在发送期间保持。GPIO配置通过ESP-IDF切回普通GPIO输出，未发现GPIO6/7仍被JTAG路由占用的证据。初始化电源与gamma参数与ARM halLcd.c逐项一致，但这不代表已验证新模块的完整初始化兼容性。

原ARM WriteComm/WriteData使用CS_L/CS_H。新板CS接低，实际构建CONFIG_DIRECT_LCD_CS_PIN=-1，跳过全部CS切换。之前将“连续写入允许保持低”等同于“启动/复位/读回无需验证CS时序”，结论不充分。

## 尚需验证的启动兼容性

后续完整核对修正：ST7789P3手册第98页8.15明确允许CS永久接地，RESET优先于CS。此前把第58页的传输中断恢复描述推成“复位后必须有CS边沿”不成立，应撤回。GPIO4接CS版实机亮屏，只证明该版本与接法可工作，不能证明该控制器必须占用CS GPIO。当前无CS只写版重点验证复位与时钟管理，mode3是实验选择而非手册规定的唯一模式。

Sitronix ST7789P3手册第48-49页说明CS高时初始化串行接口，下降沿开始传输，完成字节后可连续保持低；第58页8.4说明RESX中断传输后，接口在RESX高后下一次CS激活时准备接收命令。该描述使复位后CS激活成为候选差异，但不能单凭该条款断言所有固定CS低的模组都会失败。

第50页要求读取寄存器后CS回高，再发送新命令。SDA还必须在读取命令最后下降沿前切为高阻。因此当前固定CS接地条件下，不能随意加入普通读回后继续绘图，也不能把全0/全FF当作屏幕故障定论。

接下来先确认CS实际是电阻下拉还是直接短接GND。若可改为可控CS，可比较复位期间CS高、复位完成后CS下降开始写入的行为；GPIO选择须结合实物接线确认。没有确认根因，不应把本次审查说成修复成功。

参考：https://files.waveshare.com/wiki/ESP32-S3-GEEK/ST7789P3.pdf

## 最小初始化版的波形核对

在屏幕连接器端采集：9脚SCL、11脚SDA、10脚RS、7脚RESET；公共地接12或14脚，CS在8脚实测固定0V。逻辑分析仪按SPI mode0、MSB-first、8位解码，不依赖CS分帧。采样建议至少10MHz，覆盖上电8秒附近的初始化时段。

RS=0为命令，RS=1为参数/像素。最终RESET脉冲为高20ms、低20ms、高120ms；前面GPIO读回测试还会产生短复位脉冲，不能误认成最终脉冲。软件发送的命令及参数应是：

| 命令 | 参数 | 后续等待 |
| --- | --- | --- |
| 01 | 无 | 150ms |
| 11 | 无 | 120ms |
| 36 | 70 | 无 |
| 3A | 55 | 无 |
| B0 | 00 F0 | 无 |
| 13 | 无 | 无 |
| 20 | 无 | 无 |
| 29 | 无 | 20ms |
| 2A | 00 00 01 3F | 无 |
| 2B | 00 00 00 EF | 无 |
| 2C | 连续0000黑色像素 | 无 |

每次三色填充重复2A/2B/2C窗口设置，RED像素应是F8 00，GREEN为07 E0，BLUE为00 1F。RS必须在命令的8个时钟期间一直为低，在所有参数/像素期间为高；每个字节8个上升沿，SDA在上升沿前稳定，SCL空闲低。

这些是源码预期，不是已采集的实物波形。比较实际捕获与此表才可判定发送链路中的具体错误。
