# LCD house screen implementation

Approved reference: `docs/ui_redesign/lcd_optimization_20261016/index.html`, final 2026-10-16 typography revision. Preserve unrelated BMS/OTA work in the current `codex/l10-ble-binary-ota` checkout; no flash, deployment or Git operation is included.

## Acceptance

- Original selected two-storey raster house; native 320x240, existing six-key footer and menus retained.
- Grid upper left and battery lower left vertically arranged. PV upper right and load lower right horizontally aligned. Names14px bold white, powers16px, metadata12px. Chinese/English and both existing themes remain usable.
- PV1 voltage only. Grid/PV/load power uses existing DSP readings. Battery watts use DSP battery voltage(0.1V) times charge/discharge current(0.1A), divided by100 with integer rounding. Do not substitute BMS values or demo constants. Conflicting current directions show unknown.
- Charging/discharging/idle/stale are separate labels, no signed power prefix. Cached values stay visible, while stale data cannot animate or authorize writing.
- Wi-Fi connection and RSSI independently sampled from Wi-Fi APIs, not MQTT/cloud state. RSSI bucket changes repaint; jitter inside a bucket does not.
- Energy motion only on visible, awake home overview with fresh nonzero power and no OTA, at 5fps maximum. Other unchanged pages remain event driven. Strip hashes preserve partial SPI updates; no new frame buffer or heap allocations.

## Implementation status (2026-10-16)

Implemented in the `codex/l10-ble-binary-ota` checkout; no flash, deployment or Git operation was performed.

- Display model: `main/direct/direct_home.c/.h` (units, DSP watts, PV1-only voltage, battery watts from the same DSP sample, direction conflict, stale label, Wi-Fi buckets, animation gate). Home-only font and asset: `direct_home_font.c/.h` (114 glyphs at 12/14/16 px, 4bpp, 20,304 bitmap bytes), `direct_home_asset.c/.h` (320x192, 1,024-byte palette plus 61,440-byte index plane), regenerated by `tools/generate_home_font.py` and `tools/generate_home_asset.py`.
- Scene: `direct_ui_scene.c` home page only. Header band with "能流概览/Energy overview", clock and Wi-Fi icon; house asset at y=32 with routes for grid, PV, battery and load; labels follow the approved prototype geometry (grid upper-left vertical, PV upper-right horizontal, battery lower-left vertical, load lower-right horizontal). Names are 14 px bold, powers 16 px, metadata 12 px, baselines aligned. Names use the theme foreground colour with no backing plate in either theme; this drops the prototype's dark name plate in the light theme, which looked heavy at native size and covered the lower house edge under the load label. The six-key footer is unchanged.
- Wiring: `direct_panel_runtime.inc` samples `wifi_sta_is_connected()`/`wifi_sta_get_rssi()` once per second and computes the 5 fps motion phase; `direct_display_events.c` hashes only visible home fields plus the Wi-Fi level bucket and the phase, so stale data stops motion and RSSI jitter inside one bucket cannot repaint. Strip hashes still skip unchanged strips; no new frame buffer or heap allocation.

Evidence (host, Windows, MinGW gcc):

- `tests/run_home_ui_tests.ps1` passes: home model, home asset, home font, display events, stale display, no periodic trigger, actual panel DSP snapshot, six-key layout, UI v050, upgrade, locale, and the full ui_render fixture matrix (zh/en x dark/light, ~150 screens) with full-frame vs 16-row strip equality and guard bytes.
- Firmware build: `tmp/build_lcd_house_native.ps1` (Device profile, own `SDKCONFIG`/build dir) completes. App image `build_lcd_house/cs_inv_direct_c3.bin` = 0x190B60 (1,640,832) bytes against the 0x1A0000 (1,703,936) `ota_0` partition, leaving 0xF4A0 (62,624, 4%) free; ESP-IDF warns the partition is nearly full. The baseline image in `build_ota_v0632` was 1,552,160 bytes, so this change adds 88,672 bytes, roughly the 86 KB of asset and font tables plus the new model and scene code. The image hash changes on every build because the app descriptor embeds build time and the ELF digest; the artifact built for this review hashed to EB092946BF290253A34DB61AA76DABBEDFEA0F978FFB6100D4EA06E6C802A6F2.

Open items: on-device acceptance (distance, angle, refresh cost, cold start, flicker) and a hardware decision on the shrinking OTA headroom. Memory footprint of the extra ~95 KB application code was not measured on target.
