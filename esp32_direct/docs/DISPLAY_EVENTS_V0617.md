# 0.6.17-display-events：事件刷新与DSP发送诊断

移除每1秒重绘条件。显示内容、页面、按键、网络、OTA进度、有效性发生变化才渲染；
连续相同读数、帧时间戳、时间秒数不会重绘。主页时钟只在分钟变化时更新。
2~5秒保留样本提示改为固定 Last data，避免年龄计数重新引入每秒重绘。
没有真实样本仍显示--；真实失效5秒触发一次更新，不无限保留过期状态。

以前单次取锁失败会清掉03状态信息，导致InvS/Mode在数值与--间闪动。
显示层现在用真实03接收时间保留状态，5秒到期，OTA/Boot时清空；04保持相同逻辑。
一次循环只采集一次完整面板快照，可写性检查只在设置/确认页面运行。
图像只由原LCD任务写，原条带变化检测继续减少SPI写入；按键/唤醒/失败重试保持。

DSP任务优先级6，LCD优先级3；没有屏幕刷新自动停发DSP的分支。
单核调度和共享锁仍可能影响间隔，未经实机日志不能把DSP停机归因于屏幕。
正常00/01/02/03/04通信时隙和所有OTA协议保持原样。

新增定期日志 DSP TX health 和USB status里的 DSP_TX_HEALTH：

- age_ms：距离最近一次成功提交UART的时间。
- max_gap_ms：两次成功发送之间最大间隔；不是线路电平的实测间隔。
- gaps_over_500：超过500ms的间隔次数。
- lock_misses：正常发送时未及时取得共享锁的次数。
- hold：位掩码，1静默、2升级、4Boot、8参数无效、16未保存、32导入、64等待写入保存。

当DSP再次停机时，保留前后30秒日志和一次status。TX持续增长但RX停止与TX本身停止
是不同故障；返回故障状态与停止回复也需分别判断。目前根因未实机确认。

回归覆盖：原定时触发的失败复现；两分钟不变零重绘；可见读数/网络/分钟/页面/
按键/BMS/OTA变化；03/04取锁抖动不清空，实际过期及OTA后新时间戳；实际发送间隔统计。
新版本构建/完整回归/哈希结果以validation为准，未烧录、未确认实机停机已解决。
仅刷device/app.bin保留SN、WiFi和持久设置；0.6.16的DSP OTA、三包同步及默认包策略保留。
