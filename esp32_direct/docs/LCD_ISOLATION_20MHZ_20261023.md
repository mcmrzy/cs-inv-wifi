# LCD 20 MHz 隔离测试固件

版本：`0.6.43-lcd-isolate20`。基于当前工作区源码快照，ESP32-C3 / ESP-IDF 5.5.4。

## 固定行为

- 不初始化 Wi-Fi、BLE、MQTT、DSP/BMS、按键、普通 UI、NVS 或工厂服务。
- 保留蜂鸣器关闭、GPIO4 CAN 空闲高电平；LCD SCK=6、MOSI=7、DC=9、RESET=10，CS 外部接地，背光外部供电。
- 硬件 SPI 固定为 20,000,000 Hz；保持当前 mode 3、RESET 下首笔 SPI 配置、最小寄存器初始化。
- 启动后循环：红 → 绿 → 蓝 → 黑 → 白 → 黑白棋盘格。每幅发送完成后停留 2 秒，循环约 12 秒加传输时间。
- 棋盘格为 16×16 像素方块，左上白色，覆盖 320×240 全屏；每轮都重新发送完整画面。
- 串口输出复位原因、图案发送开始/完成、SPI 事务数和累计错误数；不进行自动 LCD 恢复或重启。
- 若从 OTA 待验证分区启动，首帧和 DISPON 发送没有 SPI 错误后确认该镜像，仅涉及 OTA 状态区，不写 NVS/工厂身份。该确认只证明软件传输返回成功，不证明屏幕正确显示。

## 实机使用与判断

通过现有兼容的升级/USB 维护流程写入对应 App 分区，保留 NVS 和工厂区；不要直接把这个文件写到地址 0，也不要照抄构建日志中包含 OTA 状态初始化的整片烧录命令。测试版运行后没有无线升级入口，恢复普通固件需使用 USB 维护流程。

先做多次完整断电启动，再观察循环运行，记录白屏/花屏/冻结发生在哪种图案、串口是否继续出现 `sent`、错误数以及复位原因。黑色阶段属于预期图案，可根据串口和后续白色判断。

| 结果 | 下一步 |
| --- | --- |
| 仍白屏/花屏，串口图案继续推进且 errors=0 | 无线运行负载不是复现的必要条件；优先核对 LCD 供电、初始化、信号链路和屏本体。SPI 返回成功不能证明屏幕收到了正确数据。 |
| 发生重启或 SPI 错误 | 先保留复位原因、错误日志及电源波形，再判断供电或软件/总线异常。 |
| 长时间稳定 | 仅能确认“无线关闭 + 20 MHz + 最小业务”组合稳定；不能直接认定无线导致欠压。下一轮保留图案循环，先单独恢复 40 MHz，或保持 20 MHz 单独恢复无线负载，并同步测量电源。 |
