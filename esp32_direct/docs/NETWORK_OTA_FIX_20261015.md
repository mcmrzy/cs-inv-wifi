# 0.6.26-net-ota：上电联网、HTTPS OTA 与中英文界面修复

本次以已交付的 `tmp/ota_v0625_source` 为基线，在独立的
`tmp/network_ota_v0626_source` 中构建。保留 0.6.25 的 DSP UART TX 和升级阶段诊断。
主目录中既有的其他实验与其他工程不进入本包。

## 日志证据与修复

用户日志设备版本为 `0.6.24-progress`。约 1.835 秒提交 Wi-Fi 连接，
1.903 / 6.720 秒分别出现 reason 203 / 205，6.803 秒关联成功，
7.838 秒取得 IP，9.349 秒 MQTT 连接成功。
203 / 205 在本机 ESP-IDF 5.5.4 中分别为关联失败、连接失败。
日志没有证明路由器拒绝连接的具体原因，也没有证明是重复连接导致这两次错误。

已复现并修复 START 事件与连接调用交错造成的重复提交；所有入口共用一次连接领取。
同凭据重复配置保留当前 IP 与连接进度。成功后记录实际信道，下次相同凭据优先扫描该
信道；不绑定 BSSID，仍可搜索其他频道。换 SSID/密码清除提示，提示保存失败不改变
连接成功结果。显式断开与 STOP 后忽略迟到的 DHCP 事件。
实际启动速度、AP 信道提示的持久化与路由器兼容性须刷机验证。

24.746 秒日志明确出现 `alloc(16749 bytes) failed`，随后 HTTPS 读取报
`-0x7F00` / `READ_FAILED`；失败上下文 `free=18596 max=8192`。
这是 TLS 读取阶段无法分配连续接收内存，不是由这份日志证明的 DSP 升级协议失败。

HTTP 接收缓冲由 8192 降至 1024 字节（失败时退至 512），远程搬运缓冲由 4608
降至 1024 字节。仅 OTA 的 HTTP 客户端设置 `HTTP_TLS_DYN_BUF_RX_STATIC`，在握手后
保留完整 TLS 接收缓冲，避免后续分配造成该大块被切碎。TLS IN=16384 / OUT=2048、
MQTT 全局动态缓冲和 12KB OTA worker 栈均保留。远程 ESP 升级使用顺序擦除，减少
下载前整区擦除的长停顿。缓冲策略依据
[Espressif HTTP client 文档](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32/api-reference/protocols/esp_http_client.html)
及本机 IDF 5.5.4 对应源码核对。

修复负读结果被转换为无符号数后无法进入续传的条件错误。重连从已写入并纳入哈希的
偏移继续，最多成功续传三次；服务器必须返回匹配的 206、剩余长度和 Content-Range，
缺失、重复、溢出、起止位置或总长不符均拒绝。不改变原有签名、哈希和目标身份校验。

## 界面

升级阶段、简短错误原因与操作提示按当前语言显示，不再把内部英文诊断消息直接画到
用户界面。原始错误码仍单独显示；MQTT/BLE 快照保留原始 message/code。
修复长版本号与连接来源重叠，补齐正在传输及错误提示的中文字库。
英文升级取消键显示 Stop。

DSP/BMS 完成页显示“传输完成”，分别说明已收到目标运行应答、尚未收到应答；
该应答不代表新固件版本已经回读确认。

## 验证与设备验收边界

已增加 Wi-Fi 交错事件、重复配置、信道学习与换路由、显式断开/迟到 IP、错误恢复测试；
OTA 测试覆盖缓冲策略、负读恢复、三次续传及耗尽、取消、超容量返回、服务器错位响应。
界面覆盖所有 OTA 状态和错误映射，52 张 OTA 中英浅深主题预览，检查字库、边界以及
整帧与 16 行分条逐像素一致性。完整回归及构建的实际结果以包内 validation 日志为准。

本次不烧录设备。固件应用包不包含分区表、NVS 或 DSP/BMS 镜像。
现场应核对启动版本 `0.6.26-net-ota`，测量上电到 IP/MQTT 的时间，再完成 HTTPS
下载、校验、重启和版本回读；同时确认升级失败/取消后 BLE、Wi-Fi 与 DSP 数据恢复。
本次不能据主机测试声称实机 OTA 已成功或保证任意路由器下的联网秒数。
