## P0 协议约定

1. INFO 保留 v2、session、完整 SN、版本、OTA 和控制能力，去掉占位 gate 与错误升级目标；新增 `framing_v1`、`direct_control_v1`、`max_message_bytes:512`。512 是控制消息上限，不是遥测推送上限。真实编码测试覆盖当前版本和 31 字节版本串，要求 INFO 不超过 480 字节。
2. 手机先订阅回执/遥测并等待实际适配器的通知开启，再发送 `open_session`，参数 `framing_v1:true,direct_control_v1:true`。回执 `status:applied` 的 `actual` 双标志为真后才就绪。这里 applied 只确认协议协商，不是 DSP 参数采用。
3. COMMAND、CMD_RESULT 使用一字节帧头：FIRST=0x80、LAST=0x40、低六位顺序号；净正文为 `min(MTU,512)-4`，完整控制消息最大 512 字节，最多 64 帧。序号错误、重复首帧、嵌入 NUL、超长和接收超时拒绝。接收缓存/队列受限，业务解析和设备写入在主循环执行。
4. 遥测保持现有数据结构。协商前最多 8 帧，协商后最多 64 帧、1024 字节；断线后恢复默认限制。过长消息不截断为坏 JSON；通知失败停止后续帧，缓存仍更新。Read/Read Blob 从 offset=0 冻结一份快照，后续片段保持同一值，断线只清除读取状态、不清除最新数据。
5. 未协商 direct 控制的 `set_param` 拒绝 `UPDATE_APP_REQUIRED`，在入设备写队列之前返回。旧版只读和既有 OTA 接口保留；不把新控制握手加成 PIN 或绑定要求。
6. 禁止 `power_on/power_off` 别名，返回 `UNSUPPORTED_ACTION`，不能再用 output_priority 冒充开关机。
7. 参数写完成仅证明 ESP 保存和 UART 同步提交时，回执为 `saved`，`actual` 含 `saved:true,submitted:true,observed:false`。App 返回 `SAVED_UNCONFIRMED`，不会把它当作 DSP 已生效。存储失败与同步超时分开；无法确认的证据不伪造为真。
8. 进程内保留 8 项、10 分钟幂等缓存；请求规范化 action/params，不把连接 session、sequence 当成不同操作。相同 command_id 不重复执行，内容不同拒绝。已接受的工作跨断线保留结果；旧 token 回调不能完成新写入。设备重启不保留缓存，跨重启查询/持久操作日志属于 P2。
9. 握手在校验、完整结果编码和缓存成功后才改变连接状态；被拒绝的请求不残留协商标志。JSON 构造检查所有必要字段分配/插入/复制；内存不足不能用残缺回执允许写入。已完整接受后的无线通知丢失仍是结果未知，不等同设备未执行。
