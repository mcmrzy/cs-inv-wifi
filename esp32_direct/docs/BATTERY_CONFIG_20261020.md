# 电池配置切换（0.6.41-battery-config）

## 行为与来源

电池类型通过整组草稿提交。LCD、BLE、MQTT 共用原生 DSP 类型：1 AGM、2 富液铅酸、3 自定义铅酸、4 带通信锂电、5 自定义锂电。旧标量 Collector/MQTT 枚举仍保留 3/4 互换，整组 API 不使用该旧枚举。

预设来自原 ARM `APP/SystemConfig.c:ReadSysParamFormEEPROM`：铅酸 56.0/54.0/45.0V，通信锂电充电/浮充 54.0V、截止45.0V，自定义16串LFP 57.6/57.6/48.0V，自定义14串NMC 56.0/56.0/48.0V。这些是源程序模板，必须按实际电池复核，不是自动识别或实机读回。旧三包没有 bulk，迁移保留其未知状态和已知的 float/cutoff，不伪造恢复值。

48V 自定义锂电限定原 ARM 支持的 LFP15/16串或NMC13/14串，同时校验每串对应电压区间、整包电压、充电电流、市电充电电流、返回电压和SOC关系。通信锂电只接受现有 BBJ 私有0x7C通路对应的协议5，不把菜单数字当其他厂商驱动。切入两种锂电模式都清铅酸均衡使能，只有模式4设置 isLiBat。

## 保存和 DSP 下发

请求必须携带读取到的 revision。配置变化后旧草稿返回 REVISION_CONFLICT。所有入口共用唯一 pending 写入；NVS 工作在主循环进行，UART owner 只收发，不写Flash、不格式化日志。

保存成功后，同一版本依次提交00/01/02以及包含充电设定、浮充、截止电压的0x2F。保持03/04轮询槽，避免实时数据被同步请求挤掉。全部四帧提交才完成操作；任何缺帧保留未完成状态和重试，已保存而提交超时不会伪装回滚。启动和DSP再次请求初始化时重发完整设置。新流程不使用语义冲突的0x24单项SOC指令，采用已核对的01三项SOC布局。

提供的DSP `ArmComm.c` 没有完整应用ACK/关联回读。`saved/submitted`只代表ESP已保存并提交，`observed=false`；不显示DSP已确认。旧25观察和用户desired配置独立，电池组保存使旧配置观察失效。

## NVS 兼容和故障

`dsp_params/record` 保持精确92字节V3格式，给旧程序读取当前模式/三包；`dsp_params/battery` 保存完整294字节记录（包含同一V3记录、版本、profile库和CRC）。先写完整记录，再写兼容镜像，最后commit。NVS跨key不提供电源中断原子性，因此启动检查版本、CRC、SN和两份记录逐字节匹配；存在已配置profile时，损坏、不匹配或镜像丢失会保留数据并停止同步，不能自动恢复AGM。存储失败不启用新RAM配置。

旧固件可以读取镜像，但不知道完整profile和0x2F恢复；这只避免其把扩展blob当损坏后自动写AGM，不代表旧版本支持完整电池功能。配置过新功能后不应使用缺少该功能的旧版本进行设置。新固件检测旧固件改写后不匹配的profile并停止同步，需要明确重新提交整组配置或管理员恢复。

## 验证范围

主机测试覆盖纯配置校验、组切换和原始帧、旧阈值保留、NVS重启/损坏/写入失败、UART四帧完成掩码、0x2F单帧失败重试、revision冲突和desired/observed隔离。LCD/远程入口和最终ESP-IDF构建记录在本轮完成后更新。

未烧录设备、未发布MQTT命令。实际DSP采用、BMS通信/失联、功率行为、断电和长期运行需设备验收。
