# LCD 40MHz、一秒复位和受限恢复

用户已确认原始 0.6.40 的 40MHz 对照版可用，要求保留 40MHz，将 LCD RESET 低电平保持约一秒，再初始化，并提供按键或自动重新初始化。

## 实现范围

- LCD SPI 配置 40,000,000Hz，Kconfig 允许上限相应提高到 40MHz。引脚及 CS 接线不变，GPIO4 继续保留给 CAN。
- 开机与恢复共用初始化函数：RESET 低电平 1000ms，在 RESET 下完成 SPI 模式准备，释放后等待 150ms，按现有寄存器顺序初始化、清屏。首次开机继续显示 Logo；恢复直接重画当前界面。
- 在按键扫描任务检测 ENTER+BACK（ESC）组合持续至少 3000ms，需要持续有效组合帧；松开后才能再次触发。请求用原子标志保存，不依赖界面按键队列有空位。扫描任务不直接操作 SPI。
- 唯一显示任务消费恢复请求。OTA 忙时保留请求，延后执行。丢弃恢复前积累的导航事件；保留当前页面、编辑草稿与参数状态。恢复不发 DSP 命令，不擦 NVS，不复位 ESP32。
- 自动重试仅针对已知初始化失败或 SPI 驱动发送错误。距上次初始化/恢复完成至少 3000ms，每次启动最多自动尝试两次。预算耗尽仍可手动请求。初始化失败后也创建显示任务，保留重试入口。
- 成功恢复后强制全屏重画；只有新首帧成功发送才恢复显示软件健康状态。历史错误计数保留，健康判断使用最近一次成功恢复的错误基线。

## 证据与限制

40MHz、一秒复位是用户指定的实验条件，不能据此断定此前故障由电源引起。当前没有屏幕回读与电源波形，无法自动识别“SPI 返回成功但像素没有显示”。没有定时重置正常静止页面。快捷恢复需要按键扫描和显示任务仍能运行；不能承诺从显示任务卡在驱动调用或整个 MCU 停止运行的情况恢复，也不通过另一任务并发操作 SPI。

本版必须从源码构建，基于当前含 41–43 诊断及此前电池配置变更的工作区；不是前两次严格以原始 0.6.40 ELF 只改时钟的对照。独立源码快照标记 `0.6.44-lcd-recovery`，主工作区版本文件及原发布镜像保留。仅提供 App 和说明，不自动刷机。

## 验证要求

实际 C 逻辑主机测试覆盖长按/松开/丢帧/时钟回绕、自动重试次数与间隔、OTA 延后、预算耗尽后的手动恢复、初始化失败仍有显示任务、恢复后全屏重画和健康状态。GPIO 边界测试验证 RESET 至少保持一秒、准备失败不释放 RESET、LCD 不占 GPIO4。回归 Logo 顺序、按键和 UI 渲染，并检查 ESP-IDF 构建、嵌入版本、镜像校验、分区和资源预算。

主机与构建结果不等于实机验收。需要实物验证冷启动、快捷键组合被正确识别、恢复时暂时黑屏后回到页面，以及 Wi-Fi/BLE/OTA 并行状态下的使用效果。

## 后续调整：0.6.46 恢复 20ms 短复位

用户反馈一秒白屏影响观感，并选择先试最小短复位方案。保留 40MHz，将共用初始化函数的 RESET 显式低电平等待由 1000ms 改为 20ms；释放后 150ms、软件复位后 150ms、退出休眠后 120ms 等待不变。正常开机及错误恢复均使用短复位，显式等待减少 980ms。没有改变网络启动顺序，没有组合键恢复或切页复位，受限自动恢复和原菜单项保留。

## 后续调整：0.6.47 首个正常 UI 帧后启动无线网络
