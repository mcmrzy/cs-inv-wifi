# 0.6.31 BMS 云端上报

## 报文与数据来源

参考 `esp32c3_l10_idf/main/telemetry/telemetry.c` 的现有 V3 心跳协议，在
`cs_inv/{sn}/heartbeat` 的 `data.run` 旁增加
`bms_summary={layout:0,bytes:[100 个整数],age_ms:...}`。
DSP 的 run 数据来源、更新时间和有效条件保持独立；不会拿 BMS 回包为过期 DSP 数据续期。

适用于当前 Device 配置启用的 BBJ 0x7C / 0x01 协议。既有 Modbus 分支的轮询行为保留，
本次不把缺少完整字段的 Modbus 回复伪造成 BBJ 摘要。

BBJ 接收先检查地址、功能码、声明长度、CRC、单体/温度数量和完整 61 字节 pack_info。
只有完整有效回复才能更新摘要和独立的 64 位单调时间戳。
收到坏帧或断开 BMS 后保留上次摘要，`age_ms` 继续增长，超过 UINT32_MAX 时饱和。
从未收到完整有效摘要时省略该组，不发布一组伪造零值。

## 字段

| 摘要偏移 | 内容与编码 |
| --- | --- |
| 0 | 电芯数量，沿用 ARM batteryCnt 的含义，不表示并联电池包数量 |
| 1 / 3 | 总压 u16，0.01V；电流 s32，0.01A |
| 7 / 9 | SOC / SOH，保留 BBJ 0.1% 原值 |
| 11 / 13 / 15 | 剩余 / 满充 / 设计容量，0.1Ah；设计容量扩展为 u32 |
| 25 / 27..58 | 16 位均衡标志 / 最多 16 节电芯 mV |
| 59..66 / 73 / 75 | 最多 4 路电芯摄氏温度 / 已收到电芯温度的最高最低值 |
| 67 / 69 / 71 | 循环次数 / 电芯电压最高最低值 |
| 77 / 79 / 81 | MOS / PCB / 环境摄氏温度，按报文类型识别，不依赖排列顺序 |
| 83 / 84 | BBJ battery_mode / battery_status 原值 |
| 85 / 89 | 累计充电 / 放电容量原值 |
| 93 / 95 / 97 | 请求充电电流 / 电压原值、system_mode |

未接收的温度槽位、独立 charging_voltage，以及不等价的 L10 warning/protection/fault
字段保持 layout 0 预留零值。这些预留值**不能证明传感器实测为零或没有故障**。
BBJ 32 位 fault_status、64 位 alarm_status、能量/时间/风扇字段不适合直接塞进
L10 的 16 位标志。本次不做未经验证的位转换；完整上传这些字段需要单独扩展服务端协议。
既有服务端 layout 0 的 SOC=255 离线哨兵、缺少温度有效位等语义仍然存在，本次不修改服务端。

## 验证与现场验收

- 新增实际心跳构造/tick 回归：缺少 BMS、有效/全零/最大值、过期、32 位时钟范围外的年龄、
  查询/重连/周期、DSP 过期拒报、OTA 静默、锁外发布、1024 字节上限。
- BBJ 摘要转换回归：字段及有符号数、不同温度类型、CRC/头/长度/数量错误、截断回复不覆盖旧值。
- 实际 BMS UART 任务回归：500ms 周期不变、成功回包才更新时间、后续坏帧不刷新摘要时间。
- 全部既有主机回归通过；现有 Go 服务端解码器直接读取 C 转换产生的 100 字节，
  验证单位、负电流/温度、容量、SOC/SOH、均衡、循环次数及过期屏蔽通过。
- ESP-IDF 5.5.4 Device 构建通过。没有烧录设备或发布生产服务。

现场更新 ESP 的 `device/app.bin` 后应看到 `firmware=0.6.31-bms-upload`。
待 WiFi 取得 IP、MQTT 连接成功，心跳将随现有启动/查询/默认180s周期上报。
INFO 级遥测日志会显示 `heartbeat queued (... bms=present age_ms=...)`；
这表示 MQTT 发布接口接受报文，不等同于服务端入库确认。
最终仍需检查该 SN 的实际 MQTT V3 报文、服务端 realtime/history 和 App/Web 显示。

`app.bin` 是 ESP 应用镜像。用现有应用 OTA 路径更新可保留设备 SN/WiFi/参数；
通过串口更新时必须先确认当前分区和启动槽，不能把它当 4MB 整片镜像或 DSP/BMS 固件。
