# ESP32 控制链路优化验证记录

2026-10-20。本轮按用户授权执行控制链路优化；服务器证书校验保持原样。保留已有工作区修改，没有提交、推送、刷机或部署。

## 已实现

- 云端写去重缓存保留 8 条、终态保留 10 分钟；纯查询、无效/过期/不支持的请求以及底层未接收的写请求不占写槽。已记录任务仍按原回执重放，载荷冲突不覆盖原结果。
- MQTT 普通命令回调只复制消息到 2 槽固定队列；主循环每次最多取一条，出队时检查期限。保留首片 retained 标志，拒绝 retained 普通写，查询允许。OTA 保留原独立处理路径。
- 队列满时拒绝新消息并计数，保持先到消息和顺序。满队列的输入不会执行，也不会立即产生任务回执；云端可能超时，USB status 的 queue_full 可用于定位。有效写缓存满时返回 BUSY，不提前淘汰仍在幂等窗口内的结果。
- 底层写接口区分参数错误、不支持、升级占用、未就绪、保存失败和串口提交失败；云端、BLE、本地屏幕显示对应原因。已保存但提交超时显示同步未完成，不声称 DSP 已采纳。
- DSP 正常原始帧只在内容变化后打印；异常按新事件判断，每类最多每 5 秒一次。受限期间保留最新证据供后续 tick 打印，30 秒摘要保留；UART owner 不承担日志格式化。
- 新增资源预算工具并接入 build.ps1。检查实际 app 二进制、实际 app 分区和 ELF 静态 RAM，合并 IRAM/DRAM 物理别名，报告主要符号占用和 SHA256。默认门槛：app ≤ 1,650,000 字节、分区剩余 ≥ 32,768 字节、静态 RAM ≤ 196,608 字节。
- USB status 增加最小空闲堆、最大连续空闲块及命令队列/拒绝/过期/缓存满计数。
