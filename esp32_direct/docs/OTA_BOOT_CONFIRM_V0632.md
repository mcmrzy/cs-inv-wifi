# 0.6.32 通信采集启动确认修复

现场日志显示，新应用 `0.6.31-bms-upload` 已启动，但 `ota_health` 连续三次
创建失败：可用堆约 15KB，最大连续块只有 7680 字节，小于任务要求的 12288 字节。
启动确认未执行，OTA 保持 busy/installing，屏幕一直显示“正在写入”。

## 修复

- 复用 `app_main` 的启动任务完成健康确认，启动栈在所有构建配置中设为 12288 字节。
  主业务循环启动、BOOT_READY 后执行确认；无需在网络和 BLE 初始化后的碎片堆中
  再申请独立任务。确认结束后随 `app_main` 返回释放启动栈。
- 保留 10 秒观察期、主循环/显示/串口/USB/身份检查、SDK 有效镜像确认和失败回退。
  网络连通不是启动确认的前提。确认成功才清理待确认记录、报告成功并解除 OTA busy。
- 重启后的待确认阶段显示“正在确认启动 / 正在检查启动状态”，通过后显示“升级成功”。
  重启后没有恢复的传输字节数不再显示为 `0 / 0 B`。
- 用户可见的 ESP/ESP32-C3 名称改为“通信采集”，包括升级目标、重启、版本和本地保存提示。
  协议中的 `esp` 目标与固件芯片校验沿用原值。
- 版本更新为 `0.6.32-ota-confirm`，保留当前工作区已有的 BMS 上报实现。

## 验证与交付边界

- 在原始代码中复现最大连续块 7680 字节时无法启动确认的失败测试。
  修复后执行真实启动确认函数，通过成功、跳过普通开机、各健康项失败、
  SDK 确认失败、版本记录保存失败及零安全版本清理测试，覆盖 Device/Production 策略。
- 全部生产主机回归通过；新增启动确认/成功界面在中英文、明暗主题下通过
  字形覆盖、整帧与分带绘制一致性及内存边界检查。
- ESP-IDF 5.5.4 Device 构建通过，实际生成配置的启动栈为 12288 字节。
- 交付文件为应用镜像 `device/app.bin`，不是整片镜像，也不是 DSP/BMS 固件。
  应用 OTA 不需要修改分区、NVS 或设备身份。
- 未烧录、未发布云端固件，未完成实机 OTA、网络重连与升级结果上报验收。
  当前已卡住的旧固件不会因为本地代码修改而自动恢复。
