# 图形界面实施计划

目标：把用户认可的黑底四方向拓扑及统一二级页实际接入ESP32-C3独立工程，生成4MB手动烧录镜像。

架构：保留direct_ui业务状态机、DSP/BMS数据及写入回读确认。使用轻量RGB565条带绘制器和已存在硬件SPI DMA，降低新增常驻内存；不要求LVGL。由同一C绘图代码生成主机预览。单条带320×16×2=10240字节，逐条带比较上次hash并仅发送改变内容，按键入队提示音不受刷新影响。

文件责任：
- direct_gfx.c/h + direct_gfx_assets.c/h：字体/图标/裁切/条带光栅化，主机可编译。
- direct_ui_scene.c/h：使用业务状态及数据构建图形页面，全部入口可达、离线为--。
- direct_panel_runtime.inc、direct_panel.c：场景与条带输送接入，SPI错误和渲染耗时保留。
- tests及主机图像工具：实际渲染截图、边界/离线/导航验证。

步骤：
- [x] 建立字体及绘图接口，主机测试验证裁切、字体测量、RGB565条带。
- [x] 实现四方向主屏、菜单/配置/编辑、参数/BMS/告警/其他页；最大值和离线状态不伪造。
- [x] 接入硬件SPI和条带脏区，运行业务回归及ESP-IDF编译。
- [x] 使用C绘图生成实际页面截图，检查布局并修正。
- [x] 合并4MB镜像、校验各段和哈希、说明实机验收未完成。

验证门槛：所有旧入口继续可达；有效/离线快照和SOC最大值截图；绘图边界测试；构建与Flash空间检查；远端实机需验证SPI/刷新/声音和网络堆峰值。预览和构建不冒充实机通过。不得提交其他项目dirty文件或自动烧录。
