# 偶发白屏与按键有声但画面不动：候选固件

版本：`0.6.42-lcd-phase-diag`，型号 CS-L10-6K2，Device 配置，ESP-IDF 5.5.4。

## 本次实机日志确认了什么

前一版 `0.6.41-startup-diag` 的设备 ELF 摘要 `84e9002c8` 与本地镜像一致。两次启动均执行完 Logo 淡出，约 2.7–2.8 秒首次界面绘制返回，`ok=1`。首次会话持续约 279 秒，显示循环仍推进，`loop_age` 约 6–21 毫秒、`errors=0`。这证明软件调用路径仍运行，不证明 LCD 接收到数据或实物画面正确。

两次启动在约 11.3 秒均报告 `BLE actual ready; advertising: CS_INV_H1ZZX0013900001P`。设备端 BLE 广播启动已有实机日志；手机能否扫描和连接仍需确认。该日志处于“没有 Wi-Fi 配置”的分支，没有验证“已有 Wi-Fi 配置但云端离线 30 秒”的新恢复分支。

用户进一步明确：有时开机正常，有时白屏；有时进入界面后卡住，实体按键仍有蜂鸣。按键蜂鸣在扫描任务内触发，不能单独证明界面任务已消费事件。

`tx` 后期停在固定计数，但显示循环继续：代码会跳过像素相同的条带，静态画面允许不发 SPI，因此不能仅凭固定 `tx` 认定死锁。本版增加页面、按键和绘制次数，继续区分软件与物理显示状态。

日志中的 SN 为 `H1ZZX0013900001P`、没有 Wi-Fi 配置，和更早日志中的 `H1ZZX00139000079`、已有 Wi-Fi 配置不同。这是日志观测；没有足够证据判断数据变化原因。本次不自动改写 SN 或网络设置。

## 本轮修正与证据边界

ESP-IDF 5.5.4 源码的 `spi_setup_device()` 在第一笔事务才调用 `spi_hal_setup_device()`，由后者应用 SPI 模式；`spi_bus_add_device()` 仅登记配置。原 LCD 路径在第一次事务前已释放 RESET。

本轮在现有无 CS、硬件 SPI 配置下，将第一笔空操作传输放到 RESET 拉低期间。其目的为在屏幕退出复位之前完成首次 SPI 模式/空闲时钟配置；第一条复位后的有效命令仍为 SWRESET，保持既有复位等待、8MHz、引脚与寄存器参数。该顺序的主机模型在修正前失败、修正后通过；这不是实际白屏或卡住根因的闭环证明。

若首笔传输失败，保留 RESET 低电平、标记失败并输出错误，不声称初始化成功。没有自动反复复位屏幕，没有重新占用 GPIO4，也没有加入寄存器读回。

ST7789P3 手册允许 CS 永久接地，并规定 RESET 优先于 CS。因此不能根据当前症状推断必须更改 CS 接线。手册来源：[Sitronix ST7789P3，8.15 节](https://files.waveshare.com/wiki/ESP32-S3-GEEK/ST7789P3.pdf)。

## 新日志怎么看

| 日志 | 证明的阶段 |
| --- | --- |
| `LCD_SPI_PRIMED` | RESET 仍低时首笔硬件 SPI 事务已返回成功 |
| `KEY_EVENT key=... queued=1` | 扫描任务将按键入队；蜂鸣并不等于入队成功 |
| `LCD_KEY received` | 显示任务已消费事件，包含当前 page/guide/blank/factory |
| `LCD_KEY applied` | 普通界面按键处理返回，显示 page/selected/action；引导、熄屏唤醒、工厂测试分支可能提前返回 |
| `LCD_RENDER ... reason=key` | 按键后绘制函数返回，包含页面、绘制次数、SPI 次数与错误数 |
| `LCD_DIAG ... page=... keys=... frames=...` | 最新页面、已消费按键次数、已返回绘制调用次数；frames 不是屏幕确认次数 |

卡住时，如果有入队而没有 received，继续查显示任务阻塞；如果 received/applied/page/frames/tx 都推进而实物画面不变，重点核对 LCD 信号和电源；如果 `guide=1`，引导页上部分按键本来只延长停留，应结合页面与按键值判断。

## 验证与使用

本地定向回归通过：真实 LCD 启动与首笔失败保护、显示观察器、离线 BLE 共存与手机/OTA 保护、启动栈/内存顺序、16 项 BLE/OTA 生命周期、实际 Logo 渲染器与缓冲边界。GPIO4/CAN 板级约束回归通过。构建与资源预算结果见交付说明末尾。

前轮完整主机套件因已有的远程命令测试缺少 `direct_battery_validate` 链接依赖而中断，本轮未改该命令实现；不能报告完整生产套件全部通过。

诊断镜像基于当前工作区，继续包含前轮已存在的电池配置等改动；主工作区 `version.txt` 保持 `0.6.41-battery-config`。独立源码快照和日志在 `tmp/lcd_reset_phase_20261022/`，构建/ELF 在 `build_lcd_phase_diag_20261022/`。未连接或刷写设备，尚未证明实机白屏/卡住已消失。

使用 App 镜像升级；不是地址 0 的整片镜像。通过兼容分区的现有升级/维护流程写入，保留原 NVS 与 factory 区，本轮不执行任何烧录或云端发布。

建议分别记录几次完整断电再上电和几次仅复位的结果，注明正常、白屏或后续卡住。故障出现后先不要重启，短按 ENTER、ESC 各一次（仅打开/返回菜单，不确认参数写入），等待 5 秒，把包含这些按键的完整日志发回。若停在手机引导页，先按 ESC 退出再测试 ENTER/ESC。区分冷启动与仅复位，有助于判断上电与运行后问题是否同源。
