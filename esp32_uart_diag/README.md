# CS-MB USB TTL 诊断固件 0.1.1

## 0.1.1 交互修复

- 修复0.1.0在探测期间把后续输入作为BUSY丢弃的问题。普通命令最多排队8条，按接收顺序执行；`QUEUED`是待执行，`EXEC`是开始执行。队列满会明确显示被拒绝的命令。
- `stop`、`q`和Ctrl+C立即中断当前操作并清空待执行队列。跨操作到达的半行输入保留，CRLF不会额外执行一次。
- 每次手工探测打印`PROBE protocol`和实际使用的`CFG`，记录收发前后RX电平，便于确认波特率与TX/RX方向已经生效。
- 连续USB输入、UART接收和监听显式让出CPU，保留ESP-IDF警告/错误输出，避免屏蔽看门狗诊断。现有日志的Saved PC落在panic入口，尚不能确定上次看门狗复位的具体触发点；本版不宣称已完成实板WDT根因验收。

专用于当前ESP32-C3板与逆变器TTL接口的通信定位。关闭屏幕、按键、Wi-Fi、BLE、MQTT、BMS轮询和OTA服务；只有USB命令行与UART0。独立工程，不修改原direct或完整面板固件。

## 烧录与连接

- USB连接板上原生USB Serial/JTAG（GPIO18 D−、GPIO19 D+），串口助手选该USB COM口，115200、8N1，关闭本地回显，发送结尾选CR、LF或CRLF均可。USB端115200不影响逆变器端波特率。
- 上电默认UART0 **TX=GPIO0 / RX=GPIO1、9600 8N1、地址1、FC03、非反相**，只保存在RAM，重启恢复默认。GPIO0接主控RX，GPIO1接主控TX，双方GND连接。按当前3.3V逻辑板接入相容TTL电平。
- 上电不会自动发送探测或写入逆变器。GPIO0/1以外的信号脚不提供切换；GPIO20/21的BMS不参与测试。
- 完整4MB镜像写`0x0`，会清除原面板的NVS、缓存和身份等配置。App镜像不是地址0镜像；初始槽位是`0x20000`，若只覆盖App必须先核对原设备当前启动槽（另一槽为`0x1C0000`）。分区布局沿用完整面板，诊断固件不能通过面板产品OTA安装。
- 可在本机运行`./console.ps1`列出串口，再运行`./console.ps1 -Port COM5`（改成实际端口）。该脚本使用已有ESP-IDF Python/pyserial；也可使用已有串口助手。
- 若没有看到开机说明，输入`help`回车即可。命令由固件回显。支持粘贴多行，最多排队8条；为便于核对，仍可逐条等待`diag>`后发送。长操作期间普通命令先排队，`stop`、`q`或Ctrl+C立即停止并清空队列。串口助手的“发送”需带换行，或者用HEX发送`03`作为Ctrl+C。测试时关闭串口助手的自动重复发送。

## 建议首次测试顺序

先各自输入下面四条，记录完整TX/RX和RESULT：

```text
status
read 0042 1
swap
read 0042 1
```

**旧源码核对：`esp32_direct/main/direct/direct_poll.c`的`DSP_BAUD`固定115200。** 若现在连的是原direct的DSP TTL接口，优先在两个方向各试一次原协议只读请求：

```text
baud 115200
format 8N1
legacy
swap
legacy
```

`LEGACY_OK`才是有效原协议应答，单纯回显不算。若仍无应答，再执行Modbus组合搜索，先搜索地址1至16：

```text
verbose 0
timeout 200
hunt 1 16
```

`hunt`覆盖当前方向及反向、9600/19200/4800/2400/38400/57600/115200/1200、8N1/8E1/8O1，读取FC03的0042单寄存器。地址1..16最多768次探测，约数分钟；`hunt 1 247`覆盖全部地址，可能持续约一小时，随时`stop`。搜索不是自动识别全部未知协议，未命中仍需核实主控支持的协议与电平。搜索成功后选择命中地址/速率/方向/格式到RAM；取消或无命中时恢复搜索前配置。

有命中后输入：

```text
status
verbose 1
read 0042 1
poll 0042 1 1000
```

连续读取确认稳定性，输入`stop`退出。`stats`查看错误计数。搜索遇到有效异常应答也停止并明确标注`EXCEPTION`，表示Modbus对端有回应；需更换所读寄存器，不能当作已经读到运行数据。

## 全部命令

**寄存器地址始终按十六进制解释**（`0042`与`0x0042`相同）；从机地址、数量、波特率、时间等按十进制解释，不把前导0当八进制。

| 命令 | 用途 |
| --- | --- |
| `help` / `?` | 打印帮助 |
| `status` | 引脚、串口格式、地址、功能码、反相、超时、驱动实际波特率、接收队列字节数、RX电平、运行时间、堆和剩余栈 |
| `stats` / `clear` | 查看累计收发/分类/校验/帧/溢出/USB输出丢字节计数；clear清计数及RX缓冲，保留配置 |
| `baud 9600` | 300..1000000，修改逆变器端UART波特率 |
| `pins 0 1` / `pins 1 0` / `swap` | TX、RX方向；换向前释放两个旧引脚路由，再配置新方向 |
| `format 8N1` | 可选8N1、8E1、8O1、8N2、8E2、8O2 |
| `addr 1` | 当前从机地址，1..247 |
| `fc 3` / `fc 4` | 当前读功能码，仅03/04 |
| `timeout 350` | 首字节等待额度，50..5000ms；单次总接收期限另加预期帧传输时间 |
| `verbose 1` / `verbose 0` | 搜索时是否打印每个请求TX/静默失败；收到字节或命中仍打印 |
| `invert none` / `rx` / `tx` / `both` | 串口信号逻辑反相，手动测试特殊接口；hunt固定非反相 |
| `read 0042 [数量=1] [地址=当前]` | 单次读取，数量1..125；显示寄存器原始HEX及十进制，不猜单位 |
| `poll 0042 [数量=1] [间隔ms=1000]` | 连续读取，同一请求起始时间间隔；收发耗时过长时不突发补发 |
| `scan [起始=1] [结束=247] [寄存器=0042] [功能码=当前]` | 按当前波特率/格式/方向搜索，首个有效应答后停止。如`scan 1 247 0000 4` |
| `hunt [起始=1] [结束=16]` | 波特率、8N1/8E1/8O1、两个方向与地址的组合搜索，FC03/0042 |
| `listen [毫秒=10000]` | 被动监听，只接收，不发请求；显示接收时间和全部收到的HEX字节。范围1..600000ms |
| `levels [毫秒=1000]` | 约每10ms采样当前RX引脚高低电平次数，范围1..10000ms；不是逻辑分析仪，恒高不能证明已经接线 |
| `loopback` | 先断开逆变器，再短接GPIO0与GPIO1。发送16字节固定测试序列，完整相同回显为EXACT_ECHO；只验证ESP本地路径 |
| `tx 01 03 ...` | 原样发HEX字节，不自动加CRC；支持`tx 010300420001`，最多256字节 |
| `txcrc 01 03 00 42 00 01` | 手工字节尾部补Modbus CRC，低字节在前；正文最多254字节。原始发送可发送任意内容，操作方决定其含义 |
| `crc 01 03 00 42 00 01` | 只计算CRC并显示应追加的两个字节，不发送 |
| `legacy` | 单次发送原direct私有协议的命令04只读请求（01 05 04 00 00 00 00+CRC）；当前引脚/速率/校验，私有设备号固定1。原direct使用115200 8N1；检验CRC及69..128字节回复格式，不发送05/06电池信息或设置命令 |
| `stop` / `q` / Ctrl+C | 停止正在进行的搜索、轮询、监听、电平采样；串口助手须将Ctrl+C实际发送为字节03 |
| `reboot` | 重启并恢复默认RAM配置 |

`legacy`用于排查TTL口是否仍采用旧direct协议；若`LEGACY_OK`而Modbus无回应，说明可继续沿旧协议方向定位，不应再把这份寄存器表当作该端口的已确认协议。

## 输出判定

| RESULT | 证据 |
| --- | --- |
| `READ_OK` | 地址、读功能码、返回数据长度和CRC均匹配本次请求；显示各寄存器原始值 |
| `EXCEPTION` | 地址和异常功能码匹配、异常码有效且CRC正确；对端在回应，但该请求未成功读取 |
| `LEGACY_OK` | 原direct命令04响应满足头/长度/CRC要求 |
| `NO_RX` | 本次窗口没有收到字节；不能仅凭此认定TX引脚实际已输出 |
| `ECHO_ONLY` | 只收到了与发送内容完全一致的一次或多次回显，不作为搜索命中 |
| `CRC_BAD` | 看到了符合预期头部和长度的候选响应，但CRC错误 |
| `UNMATCHED` | 收到字节但无匹配有效响应，包含半包、错误地址/功能或未知协议；看完整RX |

RX摘要最多保留1024字节，超出时输出`TRUNCATED`及总字节数；原始TX模式不会凭任意CRC正确的数据直接判定READ_OK。`first_rx=4294967295`表示没收到首字节。UART帧/奇偶校验错误和缓冲溢出在`stats`中累计，数据事件队列本身也有容量限制，计数不能代替示波器测量。

## 构建和验证

`./tests/run_host_tests.ps1`运行真实命令解析/报文判定及主机驱动模拟的命令执行测试；覆盖搜索回显误判、组合搜索命中/恢复/取消、方向切换、轮询停止和输入边界。`./build.ps1`使用本机ESP-IDF5.5.4。模拟通过和编译成功不等于实板连通；需要烧录后提供`status`、TX/RX、RESULT和`stats`。

固件不写NVS或eFuse。若被手动加载到原面板待确认的OTA槽，会确认当前诊断App以避免旧引导程序回滚。恢复面板功能需重新烧录面板固件。本包未自动连接或烧录设备。
