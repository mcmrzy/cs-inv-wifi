# 0.4.28 蓝牙低内存恢复策略

用户日志运行时间约 1104–1184 秒，未出现 panic 或重启。逆变器 read_ok 持续增长，read_fail=1 的最后失败时间距当时已超过 18 分钟。

释放 MQTT 后仍只有 44148 字节内部可用内存、18432 字节最大连续块，低于 BLE 启动保护值 65536/32768。旧流程在此条件下仍调用 BLE 启动、清理失败状态、等待本地窗口结束，然后每 30 秒再次释放 MQTT，造成无效模式切换。调度入口还会在每个 tick 先禁止 MQTT，在蓝牙重试计时未到时直接返回，使云端重连窗口反复关闭。

修复后，在 MQTT 释放后重新检查 BLE 准入。若仍不足且没有已连接手机或配网操作，保留生命周期与 OTA 所有权，清理自己的失败实例后恢复 MQTT。自动尝试退避 5 分钟，用户重新进入手机连接页面可显式重新尝试；若内存改善，也可正常恢复。蓝牙等待计时保持上一次已经决定的 MQTT 准入状态，天气请求和启动所有者仍能关闭准入。

没有降低 BLE 保护门槛，也没有实测证明此硬件当前内存布局能够启动 BLE。此修改处理无效重试影响云连接的问题；要使 44148/18432 状态下蓝牙可用，仍需要进一步释放内存并在实板确认。

主机测试覆盖与现场相同的内存值、自动恢复、显式请求、连续两分钟不重复暂停云端、调度退避下保留云端准入，以及既有的已连接手机保护、OTA 所有权和天气网络保护。实际 MQTT 联网、告警队列排空及 BLE 广播均需要实机确认。
