# 告警上报与验收

逆变器告警从 CRC、地址和功能码均验证通过的 Modbus 寄存器采集。独立读取 0046～0049，目标轮询间隔 500 ms，实际间隔包含其他请求和超时。每字只接受 5 秒内数据。告警编码优先采用已识别的机型，识别不到时使用已配置的机型。机型未知时可以上报数据未知或通信中断，待确定机型后再上报位告警。

## 编码与消息

- 0046、0047共32位故障，level=2；0048、0049共32位预警，level=1。source=0。
- 每一位独立编码，位号为 0～15。2KU、6KU、12KU 使用 `(寄存器地址 << 8) | 位号`，3KU 在该值上加 `0x1000`。例如 0046 bit0 对应 V1.27 的 0x4600「市电软启失败」或 3KU 的 0x5600「母线软启故障」。保留位也按独立编码上报。3KU 中文名称来自协议表 WF_Simplify，完整清单见 alarm_codes.csv。
- source=2的0x4A00表示通信中断、0x4A01表示历史缺口、0x4A02表示告警数据未知。启动10秒宽限后检测；主动搜索/升级静默不生成掉线，结束后最多等待5秒重新采集。
- 首次有效采样已有故障立即产生state=1；明确新鲜数据将对应位清零才产生state=0。过期、超时或缺失绝不当作恢复。

主题`cs_inv/{SN}/alarm`，QoS1、不保留。直接发送严格V1信封，绕过默认V2封装：

```json
{"t":1800000000,"v":1,"data":{"source":0,"code":17920,"level":2,"state":1}}
```

示例code=17920即0x4600、0046寄存器bit0；state=0表示该位恢复。云端当前严格校验只接受source/code/level/state四个字段。原完整Modbus构建的旧DSP位掩码告警路径停用，原direct构建行为不变。旧版本已缓存的V2告警没有自动改写或重建。

## 持久化与确认

128条有界队列，普通事件最多占127条，预留一条历史缺口告警。记录包含CRC、每位基线、事件序号、时间戳和SN，写入NVS命名空间mb_alarm。每次实际变化才写；发送前必须提交成功。初始化读取损坏或SN不匹配时保留原记录并停止采集，ALM黄色提示，需提取日志诊断；不会自动删除证据。NVS提交失败时保留RAM记录并重试，此时新变化尚无掉电保证。

0.4.24 使用新 NVS 键，首次启动迁移旧记录并保留旧键，便于旧版固件回滚。两种码表各有独立基线和时间戳。回滚后的旧固件只能处理旧版记录。回滚期间的记录不会自动并入已建立的新键。

一次仅一条告警在途。匹配消息ID和连接代次的PUBACK才出队，随后提交NVS。ACK前掉电、连接重建、SDK消息过期或ACK通知队列溢出都保留事件并重发相同信封，供服务端按事件键幂等。提交出队失败可能重放已收到事件，不提前删除未确认事件。

有限容量不能保证无限离线历史。满队列时保留已排队事件和未接受变化的旧基线，并排入0x4A01告警；空间恢复后补采当前状态。溢出期间来回变化的完整历史不可重建，0x4A01恢复只代表容量恢复，不代表丢失历史补齐。

没有有效UTC时暂存，不发1970时间。当前启动内按uptime回算采样时间；掉电前没有UTC的旧事件只能使用恢复后的报告时间，本机日志标记estimated_time=1。V1仅秒精度，同码同秒多次变化会将后续时间逐秒推进，避免去重吞掉事件；这不是毫秒级故障录波。

## 串口核对与云端边界

正常日志级别每30秒输出`mb_alarm: ALARM_PIPE`：pending待确认数、mqtt连接、inflight消息ID、nvs_error、lost_bursts溢出次数、fresh新鲜字掩码（F表示四字均新鲜）及四个已接受的告警基线字。`QUEUED`只代表SDK接收待发，`PUBACK`只代表MQTT Broker确认。

本机测试覆盖 131 种编码的发生和恢复，共 262 条固件消息，使用云服务源码的 V1 校验函数。云服务需同步发布告警名称字典，生效后新告警记录和通知会显示中文名称。实机上报、生产入库和 App 接收仍需验收。

现场验收：记录一项可安全触发的真实告警与恢复→核对0046～0049→核对QUEUED/PUBACK→核对服务端事件和App。另做断网重连和有未确认事件时重启，检查同码恢复正确、无重复投影。

## 工站镜像检查

从仓库根目录使用已安装 esptool 的 ESP-IDF Python 环境执行：

```powershell
python esp32_direct/tools/flash_production.py --model CS-MB-PANEL --release esp32_modbus_panel/dist/20261112-v0.4.24-full/station --check
```

离线检查覆盖清单、镜像哈希、产品标识和分区。已有同产品设备的有线更新会备份 Flash，分段写入后核对工厂身份与用户 NVS。连接实体设备后还需核对 SN、机型、屏幕与按键，并完成终检记录。

常规ESP运行日志仍遵循远程调试开关；ROM启动、panic和所有printf日志并未变为永久云日志。本次也不把未验证的BBJ BMS私有故障字段冒充逆变器告警。
