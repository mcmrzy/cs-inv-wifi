# CS系列逆变器WiFi模块功能总结

## 1. 项目概述

**设备类型：** 光伏/储能逆变器WiFi通信模块  
**项目名称：** `cs_inv_wifi_c3`（CS系列逆变器WiFi模块，ESP32-C3平台）  
**固件版本：** `V2.0.0.ESP-IDF-C3`  
**硬件平台：** ESP32-C3（WiFi + BLE 5.0 SoC）  
**开发框架：** ESP-IDF  
**所属产品：** CS-I10-6k2逆变器  

**核心定位：** 该模块是逆变器的外部WiFi/蓝牙通信网关，通过UART与逆变器主板上的ARM芯片（GD32F303）通信，将逆变器数据通过MQTT协议上传至云端，同时接收云端下行指令转发给ARM执行。

---

## 2. 主要功能模块

### 2.1 UART协议引擎
- **物理接口：** UART1（GPIO0-TX, GPIO1-RX），115200bps，8N1
- **自定义帧协议：** 帧头`0xAA`，转义字节`0x55`，XOR校验
- **支持命令：** 设置MQTT Broker、发布数据、接收命令、恢复出厂设置、心跳、设置设备SN/密钥/热点名称、ARM固件升级协议等

### 2.2 状态机管理
- **系统状态流转：** `INIT → AP_PROVISION → STA_CONNECTING → MQTT_CONNECTING → RUNNING → OTA`
- **核心职责：**
  - WiFi STA连接管理（指数退避重连，最大60秒间隔）
  - MQTT连接管理
  - BLE广播策略管理（在线时暂停，离线时恢复）
  - ARM数据超时看门告警（10分钟无数据 → 上报故障告警码13）
  - 命令去重（8槽位NVS持久化，避免重复执行）
  - 命令过期校验（300秒有效期）
  - 三阶段命令回复：`acknowledged → executing → completed`

### 2.3 MQTT通信模块
- **协议：** MQTTS（TLS加密），端口8883
- **Broker：** `jiuxiaoyw.online`（可动态修改）
- **认证：** 设备SN作为Client ID，设备Key作为密码
- **主题格式：** `cs_inv/{SN}/{topic}`
- **订阅主题：** 下行控制命令、OTA命令
- **发布主题：** 心跳、设备信息、配置、告警、并机数据、三相数据、在线状态、命令响应、OTA状态
- **LWT遗嘱：** 设备断连时自动发布`{"online":false}`到status主题
- **断网缓冲：** 发布失败时自动存入离线缓存

### 2.4 离线数据缓存
- **存储后端：** SPIFFS文件系统（`cache`分区，384KB）
- **设计特点：**
  - 写入批处理：每10条消息或60秒刷写一次，减少Flash磨损
  - 文件格式：每个批次文件是JSON数组，文件名`/cache/b<seq>`
  - 7天TTL自动过期清理
  - 最大500个批次文件
  - SPIFFS满时自动淘汰最旧批次
  - 断电安全：SPIFFS原生支持
  - MQTT恢复后异步刷写：独立任务、PUBACK确认、部分失败续传

### 2.5 OTA升级服务
**支持三种OTA通道：**

#### a) MQTT远程OTA
- 云端通过`cs_inv/{SN}/ota/cmd`下发OTA命令
- 支持`start`/`cancel`/`query`三种动作
- **双目标支持：**
  - `target=esp` — ESP32-C3自身固件升级
  - `target=arm` — GD32F303 ARM芯片固件升级
- **安全机制：**
  - HTTPS强制要求（MQTT通道）
  - Ed25519签名验证（使用release公钥，monocypher库）
  - SHA-256哈希校验（流式计算）
  - 安全版本号防回滚（每个target独立版本号）
  - 命令过期时间校验（300秒）
- **OTA状态机：** `idle → accepted → downloading → verifying → installing → rebooting → succeeded/failed`
- **状态上报：** 每5%进度或状态变化时上报

#### b) BLE本地OTA
- 通过BLE GATT服务传输固件
- 使用环形缓冲区（2KB）流式接收
- 支持ESP和ARM两种目标
- 序列号校验、流控（SPACE_SEM信号量）

#### c) HTTP本地OTA
- 提供REST API接口：
  - `GET /ota/info` — 查询设备版本信息
  - `GET /ota/progress` — 查询OTA进度
  - `POST /ota/upload` — 上传固件（支持ESP和ARM）
  - `POST /ota/cancel` — 取消OTA
- 通过HTTP Header传递元数据（签名、SHA-256、安全版本号等）
- 异步任务处理上传，不阻塞HTTP响应

### 2.6 ARM OTA子模块
- **目标芯片：** GD32F303 ARM（逆变器主板控制器）
- **传输协议：** 通过UART自定义帧协议
- **流程：** `START → DATA → END → ACK/NACK → INFO`
- **特性：** 流式传输模式、SPIFFS暂存+MD5计算、超时重试机制（最大3次，2秒超时）、取消支持、最大固件大小256KB

### 2.7 BLE配网服务
- **功能：** 通过BLE广播让手机App发现设备并配置WiFi
- **广播内容：** 设备SN、固件版本
- **热点名称规则：** 优先使用自定义AP SSID，有SN时：`CS_INV_{SN}`，无SN时：`CS_INV_{MAC后3字节}`
- **智能广播策略：** WiFi+MQTT均在线时暂停BLE广播（释放RF资源），任一连接断开时自动恢复BLE广播
- **配网成功后：** 保存WiFi到NVS，重启设备

### 2.8 NVS持久化存储
**存储的数据：**
- WiFi SSID/密码
- MQTT Broker地址/端口
- 设备序列号
- MQTT认证密钥
- 自定义热点名称
- OTA安全版本号（防回滚）
- OTA待确认信息
- 命令去重缓存（8槽位）

## 3. 核心特性总结

1. **双芯片OTA：** 同时支持ESP32-C3自身和远程ARM（GD32F303）固件升级，三种通道（MQTT远程/BLE本地/HTTP本地）
2. **OTA安全链：** Ed25519签名验证 + SHA-256哈希校验 + 安全版本号防回滚 + Boot健康检查自动回滚
3. **离线数据保障：** SPIFFS文件系统缓存，批处理写入减少磨损，7天TTL自动过期，断网自动缓存/恢复后自动刷写
4. **命令可靠性：** 8槽位NVS命令去重，300秒过期校验，三阶段ACK回复，持久化命令结果支持重放
5. **ARM看门告警：** 10分钟无数据自动上报故障告警，恢复后自动上报恢复消息
6. **多通道配网：** BLE配网 + HTTP配网双通道
7. **智能BLE管理：** 在线时暂停BLE释放RF，离线时自动恢复
8. **高可用设计：** WiFi指数退避重连、MQTT自动重连、状态机驱动、看门狗保护
9. **灵活配置：** 通过Kconfig可配置GPIO引脚、UART波特率、MQTT Broker、缓存参数等
10. **物理隔离：** UART1用于协议通信，UART0用于调试控制台，互不干扰

## 4. 通信接口汇总

| 接口 | 类型 | 用途 |
|------|------|------|
| **WiFi STA** | 802.11 b/g/n | 连接路由器，访问互联网 |
| **WiFi AP** | 802.11 b/g/n | 配网热点（始终开启） |
| **BLE 5.0** | NimBLE | 设备配网 + BLE本地OTA |
| **UART1** | 115200bps 8N1 | 与ARM芯片通信（协议帧） |
| **MQTTS** | TLS 1.2+ | 云端双向通信 |
| **HTTPS** | TLS | OTA固件下载 |
| **HTTP** | TCP 80 | 本地OTA REST API |

### 5.2 程序主循环架构
**`main_loop_task`（2ms周期）：**
1. `uart_protocol_process()` — 处理UART接收帧
2. `state_machine_run()` — 运行主状态机
3. `offline_cache_process()` — 离线缓存定期刷写
4. `ota_service_note_main_loop_alive()` — OTA健康检查心跳
