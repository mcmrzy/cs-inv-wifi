# 原ARM通信对照：DSP RX输入上拉移植修复

日期：2026-10-14；固件：0.6.11-dsp-rxfix。

用户确认原ARM能正常通信，原ARM已从ESP测试板移除/断开。
ESP运行约753秒收到16280字节，零有效帧，3255次超时；最后候选为01 12 00 21 90。
软件与接收电气配置应先与已工作的原ARM逐项对照，不能先认定DSP或线路损坏。

## 确认的移植缺口及本次修复

原App(10)/App/source/APP/SystemInit.c:272把DSP RX PA3设为GPIO_MODE_IPU。
ESP旧uart_setup只调用uart_set_pin；本机IDF5.5.4 GPIO矩阵RX路径
esp_driver_uart/src/uart.c:902-907只启用输入并连接RX信号，没有设置上拉。

本次在uart_set_pin成功后仅对DSP RX调用gpio_set_pull_mode(rx, GPIO_PULLUP_ONLY)，
保留原ARM的空闲高电平偏置。失败时清理驱动和事件队列，不启动DSP任务。
初始化打印DSP RX GPIO0 input pullup enabled，便于核对部署版本及配置。

这是确认的移植配置缺口；尚没有实机证据证明上拉缺失造成字节1异常。
采用单项对照，保留115200 8N1、110ms槽、200ms接收超时、严格长度/CRC及其他收发顺序。
BMS、WiFi、TLS、栈分配、记录缓冲和UART事件队列保持v0.6.10行为。

## 其他已确认差异与边界

- 原ARM和ESP的CRC算法相同（FFFF初值、A001多项式、低字节先发送）；03/04查询内容相同。
- 原ARM按第二字节+4计算普通帧总长；约10~20ms空闲结束候选。旧源码在超时后仍用声明长度计算CRC，
  不是可靠的“接受任意5字节短包”依据。本次未照搬潜在越界/陈旧数据行为。
- 当前01 12/41 00 21 90分别不匹配A02C/5010的前3字节CRC；01 01 00的CRC才是9021。
  解析器不会补写或规范化字节1。真实字节测试覆盖拒绝这两个候选、接受精确有效的短CMD00。
- 原ARM收到有效00/01/02后优先回复其持久参数；目前ESP只记录请求，仍未完整替代参数同步。
  完整设置包含输出电压/频率、电池类型、充放电阈值、电流限制、模式位、并机和发电机参数。
  原源码的出厂默认值不等于这台机器保存值，不能据此直接覆盖DSP设置。
- 未发现普通运行中的第二DSP UART接收者、UART重配置或console占用UART0；console是USB Serial/JTAG。

## 对照方法与验收

只更新device/app.bin保留NVS的SN、PIN和WiFi，核对0.6.11-dsp-rxfix及DSP RX上拉日志。
保持同一块板、逆变器、连接和供电，连续记录至少2分钟DSP link/capture/UART/TLS memory日志。
观察字节1是否恢复为01、有效帧或sync_requests是否增加，以及CRC/超时走势。
若只是收到有效同步请求而没有持续03/04，继续补齐真实持久参数来源与00/01/02流程，不能宣称通信已完成。
若同样错误字节持续，保留软件调查和线路实测两个方向，不依据本次局部修复结果泛化判断。
