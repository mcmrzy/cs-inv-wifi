## 不倒退的验收基线

1. 六类设备仍能直接识别：市电、发电机、PV、逆变器、负载、电池；不能用文本日志替代主能流图。
2. 充电/放电、旁路、活动/离线路径必须由已收到的DSP状态驱动，未知状态不显示为正常。
3. 保留原两种主显示模式的关键字段：电压、电流、功率、频率、负载比例、SOC、温度、模式、时间；需要切换的字段保留明确入口。主从身份仅有可靠映射时显示，否则未知。
4. 设置、参数、告警/BMS、时间及设备信息入口保持可达。原协议未支持的写入继续明确只读，不能通过美化伪装为可写。
5. 六键均有可见反馈；聚焦、编辑草稿、发送中、DSP回读确认成功、失败、取消必须区分。按键采集不得被刷屏阻塞。
6. 告警采用图标+文字+颜色；离线与未知用OFFLINE/--，不展示上次数据为当前正常状态。
7. 在真实320×240像素下检查长值、英文标签、最大告警文本、最大参数值，不裁切关键数值。

## 方案比较

| 方案 | 收益 | 代价/条件 |
|---|---|---|
| 黑底图形 + LVGL局部绘制（推荐方向） | 统一布局/焦点/样式、数字字号、菜单和状态提示便于维护 | 需量测内存与显示吞吐；硬件SPI通过实机验证后再考虑能流动画 |
| 黑底图形 + 当前轻量绘制器 | 增量内存较少，保持现有业务状态机 | 自行维护字体、图形、裁切、脏区和键盘焦点；也需要提高传输吞吐 |
| 原ARM界面按像素移植 | 可清晰对照旧界面作为恢复基线 | 原拥挤布局和小字体也一并保留，不适合作为最终提升方向 |

## 推荐视觉方向

黑色背景、暗色区域、白色数值；青绿色表示活动，灰色表示闲置/未知，琥珀色警告、红色故障。主屏保留中央逆变器及外围能流拓扑。加入设备图标，重点显示负载功率和SOC，次要电压/电流/频率在两种模式中呈现。顶部为通信/时间，底部为按键提示和报警状态。

设置页面用对齐的名称/数值列表，明显选中态；进入编辑后显示修改草稿和确认提示。BMS页面显示汇总、单体格、最小/最大/差值；仅有实际协议数据的字段显示数值。告警页面提供当前有效告警与详情，保留原文本含义。

arm-vs-dark.png为第一轮主屏对比草案；右侧仅展示布局和字号方向，还没有完整图标、二级页面与全部运行状态，不作为最终验收图。

## LVGL与显示性能

LVGL可采用RGB565 PARTIAL模式，320×24×2单缓冲为15,360字节。该数值只计算绘制缓冲，不含对象、字体、任务、TLS/BLE等内存。整屏RGB565为153,600字节，不选整屏双缓冲。必须量测最小剩余堆、最大连续块及网络连接/OTA时峰值，不能以一次READY堆值证明可用。

当前软件SPI每位至少两次2us延时，时钟理论上限250kbit/s。整屏153,600×8/250,000=4.9152秒，仅算线上的最低传输时间，GPIO调用和任务等待会更慢。LVGL不会消除此限制。

实施顺序建议：保留当前低速GPIO驱动作为可回退路径；先以相同GPIO/CS恒低/模式3/命令时序验证硬件SPI低速写屏，之后逐步提高速度；再接入LVGL局部刷新和按键输入，最后加入小面积流向动画。不预先承诺帧率或实机响应时间。

## 文件责任与验证顺序

- 显示驱动：direct_panel.c；维持已确认接线及初始化流程，负责传输与flush。
- 界面呈现：单独图形视图模块；当前direct_ui状态/参数写入结果作为业务边界，不让渲染器直接写DSP。

- 数据：direct_link / direct_protocol / direct_energy；UI改版不随意改变通信单位或功率控制协议。
- 验证：源码页面/字段覆盖 → 320×240静态图及六键预览 → 状态机与构建 → 硬件SPI/实机按键/通信 → 网络与OTA内存峰值。构建和预览不代替实机证据。
