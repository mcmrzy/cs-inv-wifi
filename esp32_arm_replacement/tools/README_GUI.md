# CSERGY 设备服务工作台 v1.2.0

解压完整压缩包，双击 CSERGY_FactoryTool.exe，无需安装 Python。保留随包 firmware 目录。

## 当前设备使用步骤

1. 在连接设备的电脑上打开工具，关闭占用同一串口的串口助手。选择设备 USB 串口，点击“识别设备”。
2. 旧版 Device/Production 可能显示“需更新同配置固件”：旧版把诊断错误地归入身份写入权限，返回 WRITE_DISABLED，不代表硬件损坏。
3. 进入“固件维护”，当前开发单机选择 device，使用随包 v0.6.7-onboarding-dev。首次迁移选项保持未勾选，点击“备份并更新固件”。先整片备份，再分段写入并校验，保留身份和用户设置。分区不匹配会停止。
4. 完成后断电重启，重新识别。进入“检测工位”启动测试，逐个按六个按键，约两秒刷新一次“已按”；观察屏幕和蜂鸣器，手动选择通过或失败。
5. 点击“保存报告并结束诊断”。报告、日志、备份保存在“工位数据”，侧栏可以打开或更换目录。

诊断不需要切换 Factory。连接中断后新固件约60秒退出测试；正常查询会续期。

## 功能范围

- 设备识别：读取实际固件版本、型号、MAC、SN和权限，旧固件缺少运行SN时明确提示。
- 实时测量：读取DSP/BMS现有数据快照，离线时明确显示未收到数据。
- 屏幕/按键/蜂鸣器：固件执行诊断，按键逐个显示，屏幕和蜂鸣器由人工观察。
- 固件维护：检查SHA256、整片备份、分段写入和读回校验。
- 身份工单：仅未锁定Factory允许写入；逐台SN绑定实际MAC，写入读回后断电重启复核。
- 身份锁定：要求实际硬件版本和报告引用，锁定后普通接口不能改写。
- 检测报告：缺少误差标准、仪器参考值或实际验证的项目保持待验证，不自动判通过。

本版没有自动完成电气校准、带载验收或DSP/BMS校准系数写入。BLE/MQTT升级仍由原有固件通道执行，此EXE维护页为USB烧录入口。

## 配置选择

- device：当前单机默认SN H1ZZX0013900001P，可管理员修改，身份受保护，诊断可用。
- factory：逐台写生产身份，诊断可用。
- production：读取生产身份，禁止普通身份写入，诊断可用。

工单示例SN为空。未知硬件版本可暂填UNSET，但不能锁定。生产时间使用UTC。

## 异常处理

WRITE_DISABLED诊断拒绝：同配置更新v0.6.2，再识别。身份写入拒绝：检查是否Factory以及身份是否锁定。
设备未回复：检查上电、USB串口、其他串口程序占用。
OTA忙：等待升级完成。
固件校验失败：重新解压完整包，不混用不同版本文件。

工具不会自动选串口或烧录。实际烧录由操作者点击开始。完整4MB合并文件会覆盖用户存储；工具采用备份后分段写入。

## v1.2.0 烧录速度
默认传输波特率为2,000,000，整片备份、固件写入、校验与身份读回均使用该速率。固件维护页可选择较低速率；不会失败后自动改变速率重写。芯片擦写、压缩与USB处理仍需时间，实际耗时取决于设备。扫码配对身份需要 v0.6.7-onboarding-dev 固件能力。

## v1.2.0 单个BIN烧录
固件维护页面下方点击选择BIN文件，再点击备份并烧录所选BIN。类型可切换应用固件与完整4MB合并固件。默认2M传输。
应用固件写到0x20000并重置OTA选择，设备须采用本项目分区；保护现有NVS和factory区。完整4MB合并固件写到0x0，覆盖SN、设置和缓存。确认窗口显示范围、地址、大小、SHA256。两种方式均先备份、再写入及校验。
仅支持有效的ESP32-C3明文镜像。bootloader.bin不是应用固件；不是4MB的合并文件或需要其他地址的程序，请使用原有完整固件目录方式。

## v1.2.0 扫码身份 / PIN

本包固件为 v0.6.7-onboarding-dev，新增扫码身份能力。此版本仍需要真实手机、二维码识别与设备联调验收；工具读回成功不能替代这些验证。

### 量产 Factory 工位

1. 使用受控工位环境配置 `PRODUCT_SECRET`，其值必须与正式后端配置相同。由管理员通过受控环境管理设置；不要写进工单、脚本、发布包、截图或日志。
2. 在同一环境启动 EXE。工具只在执行写入时读取运行环境；EXE 不携带产品密钥，界面也不显示它。缺少配置会明确停止写入。
3. 给每台设备写入唯一的16位大写字母数字 SN 与完整工单。不要批量使用开发默认 SN。
4. 断电重启，点击识别设备，确认运行 SN 与身份工单 SN 一致。
5. 点击身份页“写入扫码PIN”。工位生成与后端一致的六位 PIN，写入后由固件读回比较，工具重新查询配对就绪状态及 SN。
6. 去屏幕“手机连接”页验证手机扫码。随后完成检测和实际生产验收，再锁定身份。新固件能力声明存在但 PIN 未就绪时，工具拒绝锁定。

首次写入、写入 PIN、锁定是独立动作，不会隐式自动锁定。旧固件缺少配对能力时按钮不可用，不发送新写命令。SN 变更会使旧 PIN 失效，需要重新生成并写入。

### 已有 Device 设备补写

GUI 的二进制身份/PIN 写入仍受 Factory 权限保护。Device 使用 USB 串口已认证文字命令，管理员密码与绑定 PIN 是不同的值：

```
set_sn <管理员密码> <16位大写SN>
```

看到成功后必须重新上电。确认 `status` 返回新 SN，再使用管理员提供、与后端匹配的 PIN：

```
set_pin <管理员密码> <当前运行SN> <六位PIN>
```

每条命令附加换行。未持久配置 SN 的默认 Device 必须先写 SN；不可凭默认字符串直接补 PIN。PIN 保留前导零。PIN 生成来自受控后端/工位，不应手工猜测或随意生成。串口助手和 EXE 不要同时占用 USB 串口。

Product secret / 服务端签名私钥均不随此工具分发。普通识别报告只包含配对是否就绪，不包含 PIN。
